**Ninth-digest capacity interpretation — user-approved 2026-09-30:** the accepted APOL v1 header has exactly **eight** SHA-256 slots and requires all unused bytes zero. The user chose to preserve v1 and accept an **issuer-side** typed `NoSpace` for a ninth *distinct* digest before any state mutation/signature (`Policy::add_revocation` pure-model host test, original bytes compared), alongside an authentic root-signed *eight*-digest policy accepted in the real guest. This is an explicit narrowing of the earlier literal guest-ninth test; **no guest ninth-digest artifact exists and none is claimed**. Changing the header, reserved bytes or IPC padding would require a separately approved signed-wire/public-ABI decision. Fifth policy and third stage **are** guest-tested typed pre-CREATE NO_SPACE.

**Stack safety:** the guest's kernel-derived entry stack is one 4 KiB page. Measured optimized static stack frames include 4,920 B in the Rust service entry, 2,392 B in scan, and 3,576 B in dalek's serial double-scalar verifier, so that page is insufficient. Image26's assembly entry switches *before Rust* to a separately aligned, statically mapped 32 KiB `.bss` stack, while 4,288-byte file and 4,239-byte Ed25519 message workspaces live in distinct `.bss` arrays. No syscall, kernel stack change, allocator or executable window was introduced. The real guest acceptance tests execute the nested signature path. The bound is package-private; future dependency/compiler/backend changes require renewed stack audit.
