# ADR-0053 exact-source audit — accepted for pinned verifier configuration (2026-09-30)

**Source/host acceptance gates passed; guest implementation/qualification is separate.** This records independently repeatable evidence, not a formal proof of correctness for all 1,005 third-party files or any changed configuration. The complete unsafe inventory/review and two coverage-guided campaigns are recorded in [0053-unsafe-review.md](0053-unsafe-review.md) and [0053-fuzz-evidence.md](0053-fuzz-evidence.md). Guest structural authority, persistence and QEMU proofs remain outstanding.

## Source and provenance

`crateFiles.zip` contains all 23 exact `.crate` names, no extra names or symlinks; all 23 SHA-256 archive digests match the *preexisting* registry-index table in ADR-0053. `python3 tools/phase84_zip_unpack.py --zip crateFiles.zip --out build/phase84-crates` validates all ZIP member names/types/sizes/archive hashes **before writing any output**. `python3 tools/package_vendor.py --archives build/phase84-crates --out build/phase84-sources` independently verified and extracted the complete closure, then those bytes were copied into `vendor/phase84/`. A fresh second extraction into ignored `build/phase84-zip-source-proof/` was byte-identical to committed vendor sources by `diff -qr`; a mutated archive was refused with no partial output directory. The original zip is retained for offline reproduction (not used by Cargo). No substitution of git tags or versions. `python3 tools/phase84_source_manifest.py` compares **every extracted file SHA-256** against Cargo's generated `.cargo-checksum.json` and archive SHA-256 against ADR-0053; it also emits a sorted tree digest, registry-published `.cargo_vcs_info.json` git SHA-1, declared license string and included license-file names for all 23 crates. Full machine-readable table: [`audit/phase84-crypto/SOURCE-MANIFEST.tsv`](../../audit/phase84-crypto/SOURCE-MANIFEST.tsv). Upstream SHA-1s are publisher-declared provenance, **not independently authenticated upstream commits**; archive hashes are the binding source identities. An altered vendored README was refused by the manifest tool in a reversible test.

All crates include license files. Declared terms: most MIT/Apache-2.0; `ed25519-dalek`, `curve25519-dalek`, `subtle` BSD-3-Clause; `generic-array` MIT; dormant `fiat-crypto` also BSD-1-Clause; dormant `unicode-ident` also Unicode-3.0 (license text included). `MIT/Apache-2.0` in two upstream manifests is older dual-license notation. Exact declarations and texts are preserved in the vendor tree; no product-wide license clearance is implied here.

## Offline feature/target/build evidence

`audit/phase84-crypto/` is **audit-only**: `#![no_std]`, exact `ed25519-dalek =2.2.0` and `sha2 =0.10.9`, both with defaults disabled, full 23-package Cargo.lock, repo-vendored source replacement, offline mode and `--locked`. [`FEATURE-TREE.txt`](../../audit/phase84-crypto/FEATURE-TREE.txt) records the *effective serial-backend target* feature graph. Notable nondefault library features include curve's `digest`, `digest`'s `core-api`/`block-buffer`, and `generic-array`'s `more_lengths`; some transitive defaults remain enabled (see the exact tree), and the host-only semver build dependency enables `std`. No `ed25519-dalek` rand/PKCS8/PEM/batch/serde/alloc features and no guest `std` are selected. **Important nuance:** `ed25519-dalek 2.2.0` unconditionally compiles/exports `SigningKey`/signing source even when defaults are disabled; there is no feature to remove that API. The audit probe imports and calls **only** `VerifyingKey`/`Signature`; eventual guest code must expose a verify-only wrapper, hold no secret material and confirm the final linked image has no used signing path. Never infer 'no signing API exists' from the feature tree. Cargo.lock also contains target/conditional alternatives that are **not** built in this configuration: `fiat-crypto`, `libc`, `curve25519-dalek-derive` and its `proc-macro2`, `quote`, `syn`, `unicode-ident` host closure. They remain hash- and license-pinned, not silently removed from the reproducible lock.

On Rust 1.97.0, default curve `simd` cfg aborts the **compiler** with LLVM SIGILL when code-generating the optimized `x86_64-unknown-none` crate at opt levels 3, 1 and `s`; ordinary `cargo check` and optimized native Linux compilation pass. This is not evidence of a guest CPU exception. The exact crate's documented build script supports `curve25519_dalek_backend="serial"`; audit-only `.cargo/config.toml` explicitly selects it. With that cfg, an optimized `no_std` target build succeeds from a **fresh empty CARGO_HOME**, `--offline --locked` and local vendor source only (`build/phase84-clean-build.log`). No patch to any authenticated crate, dependency, signature algorithm or wire format. On `x86_64-unknown-none`, `rustc --print cfg` reports only `fxsr` (not `avx2`); vendored `cpufeatures/src/x86.rs` returns false instead of running CPUID on `target_os="none"`, and curve's `backend/mod.rs::get_selected_backend()` falls back to **Serial** even if SIMD code were compiled. Thus for the frozen target flags the explicit cfg excludes unreachable SIMD/proc-macro code and preserves the actual runtime arithmetic backend. If target features or OS change, repeat this review before reusing that conclusion.

The **active** build scripts are `curve25519-dalek/build.rs` (bits/backend/version cfg from target environment and `rustc_version`) and `generic-array/build.rs` (`version_check` rustc version probe). `libc`, `proc-macro2`, and `quote` build scripts are present in the pinned sources but not run under the serial target graph. Inspected dormant `proc-macro2` and `quote` scripts invoke only local `rustc` feature/version probes (and `proc-macro2` writes/cleans `OUT_DIR`); no network fetch. The SIMD-only `curve25519-dalek-derive` proc macro is not loaded into the serial audit build. This narrows the executable supply-chain surface without asserting a full unsafe audit.

## Independent crypto checks and remaining review

`cargo test --offline --locked --release --target x86_64-unknown-linux-gnu --test vectors` on the *same vendored, serial-configured dalek/sha2* passes RFC 8032 public vectors 1 and 2, both separately OpenSSL-signed frozen ADR-0053 package and policy message domains, SHA-256 `abc`, and altered-message/signature/wrong-root/domain, noncanonical scalar, small-order point/key, invalid key and length rejection (plus 512 deterministic signature bit mutations). **Security-relevant finding:** dalek's ZIP-215-compatible `VerifyingKey::from_bytes` *does* decompress some noncanonical, non-small-order public-key encodings. The audit-only verify wrapper now rejects them by recompressing the decoded point and requiring exact byte equality, in addition to rejecting weak keys and calling `verify_strict`; a test enumerates real offending aliases, proves dalek accepts their decompression and the guard refuses them. Carry this guard into the eventual guest decoder; `verify_strict` alone is not a proof of canonical signer-key bytes. The audit test stores only public keys/signatures; no signing material. `python3 tools/test_package_record.py` passes 6/6 (10,000 seeded malformed-record mutations, independent OpenSSL checks for surviving parses) and `python3 tools/test_package_vendor.py` passes 3/3. These are **host** unit/vector checks; separate decoder-transition and instrumented-Rust coverage-guided fuzz evidence is in [0053-fuzz-evidence.md](0053-fuzz-evidence.md). None proves guest validation.

Initial static inspection, completed and bounded in [the unsafe review](0053-unsafe-review.md): dalek verifier source has no actual `unsafe` blocks (its `unsafe` mentions are comments); serial curve uses a volatile-read optimization barrier; precomputed-table pointer cast is feature-disabled. SHA-2 and cpufeatures contain target-feature x86 intrinsics, but freestanding cpufeatures refuses x86 runtime detection and SHA-2 takes software compression; SHA-2 also contains a `compress256` `GenericArray<u8, U64>` / `[u8;64]` layout cast (the direct-compression feature is not enabled here). `subtle` uses volatile-read barriers and a representation cast of `Ordering`; `block-buffer` uses cursor-invariant `unreachable_unchecked` and block slice casts; `generic-array` has extensive unsafe layout and partial-initialization/iterator logic. The 724-site lexical inventory, active-site preconditions and dormant/host-path exclusions are documented in the completed pinned-configuration review; both parser-transition and instrumented-Rust source-region malformed-artifact campaigns passed. This does not approve activating dormant paths. `libc`'s numerous target-specific unsafe definitions and the SIMD/proc-macro closure are dormant for this target but remain pinned; an inadvertent feature/cfg change must fail review. No network-capable or runtime code generation was identified in active crate sources, but this is not a formal exhaustive proof.

Reproduction from repository root (run Cargo **inside** the audit project so its local source replacement is applied):

```sh
python3 tools/phase84_zip_unpack.py --zip crateFiles.zip --out build/phase84-crates
python3 tools/package_vendor.py --archives build/phase84-crates --out build/phase84-sources
python3 tools/phase84_source_manifest.py | cmp - audit/phase84-crypto/SOURCE-MANIFEST.tsv
python3 tools/test_phase84_zip_unpack.py
python3 tools/test_package_vendor.py
python3 tools/test_package_record.py
. tools/dev-env/env.sh
(cd audit/phase84-crypto && cargo build --offline --locked --release --target x86_64-unknown-none)
(cd audit/phase84-crypto && cargo test --offline --locked --release --target x86_64-unknown-linux-gnu --test vectors)
```

`phase84_zip_unpack.py` and `package_vendor.py` refuse existing output directories; choose fresh ignored output paths or remove only temporary `build/` outputs before rerunning. Neither command mutates committed vendor sources.

**Accepted audit boundary:** the pinned/source-checked serial x86_64-unknown-none verifier, independent vectors and bounded coverage-guided decoder/Rust fuzz gates passed. The ordinary hardening finding that a separately supplied subordinate must equal the root-signed policy bytes is enforced in the Rust host oracle; the guest decoder must enforce it too. Next implement the guest receiver, its own malformed-artifact refusal proofs, persistence/rescan and final QEMU image qualification. Never treat `cargo check`, host OpenSSL, coverage feedback or exit status alone as guest semantic PASS.
