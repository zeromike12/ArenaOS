# ADR-0057 — Phase-9 compositor authority and input protocol plan

Status: **Proposed extension to ADR-0056; no runtime implementation or qualification claimed**
Date: 2026-10-01

## Why a second protocol design is necessary

The historical IPC v1.1 call has two words, an optional 64-byte inline message and one optional transferred capability. It does **not** authenticate the caller by process ID. The qualified Phase-8.5 dynamic-child limit is one unretired child system-wide; two concurrent windows cannot be implemented by lifting that bound. BootImage indexes 0/1 currently embed displayd and the short-lived shared-memory test fixture, while only two more indexes are available. Four production graphics processes (displayd, compositor, client A and client B) plus the probe need five indexes; allocate indexes 0..3 to production and index 4 to the test-only probe, with an explicit five-entry bound and unchanged `Image` dynamic ID namespace. This is *not* permission to raise cap slots, inherited grants (5), Notifications (18), or unrelated process limits. Only two new endpoint objects fit the ADR-0056 10→12 decision: display-present and compositor-client/input. The current display endpoint is a parked boot-synchronization witness, not a typed readiness protocol.

## Possession and wire authority

Define typed GRAPHICS v1 frames in the existing 64-byte inline IPC payload: `AGFX` magic, byte version 1, byte operation, two zero header bytes; little-endian handle at 8..16, signed x/y at 16..24, bounded width/height at 24..28, key/pressed at 28..30 and zero reserved tail 30..64. Pure codec covers CREATE, MOVE, DAMAGE, FOCUS, DESTROY, KEY, PRESENT and MODE; it refuses noncanonical reserved fields and geometry before output mutation. IPC's transferred cap is **separate** from this payload. The pure `no_std` codec and model pass eight host tests and bare-metal build, but have no running compositor or authority bridge. Actual service replies still require explicit typed refusal codes. The request's transferred cap is consumed on **every** path; refusal cannot leave a landed authority in the receiver. Display PRESENT requires a compositor-held designated shared scanout cap and a separate endpoint call cap. Display compares the landed SharedRegion kind/full generation against its *own* backing cap using `SYS_CAP_DESCRIBE` and checks the received rights; a physical number, request ID, endpoint name or a borrowed caller PID never grants the operation. With the framebuffer/GPU BAR held solely by displayd, no other process maps MMIO. The generic shared-region registry's eight-object / 2048-page ceiling remains, so scanout (≤512 pages) plus six 320×200 client surfaces (at most 20 pages each) fits after the boot probe retires; table-full refuses before resource mutation.

The display endpoint's next bridge must implement MODE and PRESENT **before** clients are started: MODE, requiring only the explicitly granted endpoint WRITE cap and a canonical AGFX v1 frame with no transferred cap, replies with checked width/height in the two IPC words, the canonical AGFX v1 MODE inline frame, and a copied, attenuated scanout SharedRegion cap. Only the compositor receives the endpoint/grant in the production topology. PRESENT requires a separate transferred scanout cap: displayd compares its full generation against the region it created, checks kind=7, minimum READ/WRITE rights and held `SYS_SHARED_INFO` size, clips/rejects geometry against the actual mode, and destroys the *landed* reference on every branch, including malformed requests. It then copies only checked rectangles to GOP MMIO or submits 2D TRANSFER/FLUSH with strict ACKs, returning a typed status and the canonical AGFX v1 PRESENT echo on success. Raw cap-slot numbers or resource IDs in the wire are never authority. This bridge is **not yet implemented**; the current endpoint still refuses all calls.

Each CREATE supplies an attenuated SharedRegion cap. The compositor checks kind=7, rights and backing size. Add `SYS_SHARED_INFO=39` as a **read-only generic SharedRegion query**: caller must hold an actual SharedRegion/READ cap, present a writable 16-byte output and zero reserved arguments; the kernel returns [full generation ID, page count] from the live registry, never a physical address. A stale/wrong-kind/attenuated/noncanonical/bad-address call refuses before touching output. Neither ID nor caller-declared geometry is authority; the receiver validates the cap and checks `(pitch × height × 4) <= pages × 4096` before accepting a CREATE. This is the smallest missing generic information needed for untrusted surface dimensions; it does not mint a region, change `CAP_SLOTS` or raise any table bound. It holds one cap per occupied surface, records the object's full nonreused generation, dimensions, position, explicit z-order and focused surface; later MOVE, DAMAGE, FOCUS and DESTROY must *also* carry a matching attenuated cap. An arbitrary numeric surface index does not confer authority. At most six surfaces from four clients, opaque XRGB, max 320×200; reject overflow and any unrepresentable dimension before changing state. Composite into a display-owned/shared scanout only through an explicitly granted mapping, clip both surface and screen using checked i64 coordinates, and send a bounded PRESENT to display. Slot reuse advances generation, and stale surface handles are refused. A client cannot nominate the display framebuffer as its surface. Compositor death is fail-closed; no nominal-name takeover, silent window resurrection or restart claim without an explicit owner-cap protocol and demonstrated guest teardown.

Inputd's production grants are currently four slots, with a fifth available under `MAX_INHERIT=5`; its diagnostic fixture is a separate spawn with a slot-4 marker and must remain untouched. The production fifth grant can be an attenuated generic **inert token** (no syscall authority, one immutable kernel-minted boot token ID). The compositor holds a separate READ comparator for that *same token object*. A keyboard event is accepted on the shared compositor endpoint only if its one transferred cap is precisely this token with the expected rights; an event opcode alone or an endpoint WRITE cap is not producer authority. Existing `Notification` capacity stays 18/18; no new notification is minted. Inputd keeps its old console-injection behavior and additionally forwards actual decoded virtio-input events. Compositor focus policy alone determines which bounded client queue (≤16, overflow explicitly refused/counted) receives a key. Clients never get the input-producer token; copied token authority is intentional only if the holder explicitly delegates. Pointer is optional and not claimed without a real QMP-injected device event.

A pure, separately built `no_std` compositor state model may be host-tested before the IPC/death bridge is written. Its opaque numeric owner and region IDs are **only already-verified descriptions**; no model API is a source of authority and no host test is a ring-3 compositor or input proof. Do not wire the model to untrusted IPC without the concrete cap-describe/landed-cap and lifecycle checks above.

**Unresolved lifecycle requirement before shipping:** capability possession authenticates a surface, but it does not prove the original client is alive after the compositor has copied the surface cap. A client-origin cap alone cannot implement automatic dead-owner cleanup. Bind each fixture client to a manager-owned Process cap (or an equivalently receiver-verified lifecycle capability) and prove that compositor revokes surfaces on real death/retirement *before* a reused slot accepts any request; exercise death during queued IPC, boot-child/resource budgets and service failure. If this cannot be demonstrated, do not claim completed windows/focus/restart. Likewise do not present a visual model or a serial marker as independent QMP pixel and injected-input evidence. ADR-0056's full graphics exit gate remains in force.
