# ADR-0018: IPC v1 — endpoints, synchronous call/reply, badged notifications, capability transfer

- Status: accepted
- Date: M4.4 (first user process shipped; two processes must now talk)
- Relates to: ADR-0006 (kernel/user boundary philosophy), ADR-0013 (scheduler),
  ADR-0015 (capabilities), ADR-0017 (syscall ABI v1), ARCHITECTURE §7 (IPC philosophy)

## Context

ARCHITECTURE §7 commits ArenaOS to three IPC primitives — synchronous
call/reply over endpoints, badged merged notifications, and shared-memory
channels for bulk data — under one rule ("never copy what you can share")
and one naming rule (no global names; services are reached by capability).
M4.4's ROADMAP step asks for the smallest honest slice: endpoints, sync
call/reply, notifications, capability transfer inside messages, and an
echo-server demo across **two processes**. The scheduler so far has only
Ready/Running/Zombie — there is no way for a thread to *wait* for another.
Capabilities exist (ADR-0015) with kinds `Process` and `Memory`, but no
communication object kinds.

## Decision

### Objects and capabilities

Two new kernel object kinds, reached only through capabilities:

- **Endpoint** (`CapObj::Endpoint { eid }`) — a rendezvous point for
  synchronous call/reply. Rights map onto the existing mask:
  `WRITE` = call side, `READ` = serve side (recv/reply).
- **Notification** (`CapObj::Notification { nid }`) — a badged, merged
  event flag word (L4 lineage, §7.2). `WRITE` = notify, `READ` = wait.

Object creation is a kernel-side API in v1 (`ipc::create_endpoint` /
`create_notification`); *user-driven* object creation belongs to the M4.5
root-task/spawn-protocol step, which decides who may mint what.

### Messages

A v1 message is **two 64-bit words** plus **at most one capability**,
copied inline — the small-message fast path §7.1 describes. Bulk data is
explicitly deferred to shared-memory channels (§7.3): the kernel must not
copy what processes can share, and v1 refuses to grow a big-copy path
that would make the lazy choice easy later.

### The five calls (ABI v1 registry, ADR-0017 frozen slots 7–11)

| # | Call | Args (RDI/RSI/RDX/R10/R8) | Returns | Blocks |
|---|------|---------------------------|---------|--------|
| 7 | `ipc_call` | ep slot, w0, w1, send-cap slot (`u64::MAX` = none), reply-buf user VA | `STATUS_OK`; reply lands in buf: `[w0, w1, cap-slot-or-MAX]` | yes |
| 8 | `ipc_recv` | ep slot, buf user VA (24 B) | `STATUS_OK`; buf as above | yes (until a request arrives) |
| 9 | `ipc_reply` | ep slot, w0, w1, send-cap slot | `STATUS_OK`; wakes the caller | no |
| 10 | `notify` | notification slot, badge (nonzero) | `STATUS_OK`; badge ORs into pending | no |
| 11 | `wait` | notification slot | pending badge word (positive payload), then clears it | yes (until pending ≠ 0) |

All user buffers are page-validated against the calling thread's
registered regions (ADR-0014/0017 discipline) and touched through
STAC/CLAC; a bad buffer is a typed status, never a fault.

New typed status: `STATUS_BUSY = -4` (bounded queue full; a second
server `recv` on one endpoint; a second `wait` on one notification).
A cap transfer that finds the receiver's space full is not an error —
the cap is dropped, the message lands with `CAP_NONE` in its cap word,
and a `cap_drops` counter records it (safe because v1 caps describe,
never own — see Consequences).

### Rendezvous semantics

`ipc_call` enqueues the request on the endpoint (bounded queue, depth 4)
and **blocks** the caller. If a server thread is parked in `ipc_recv`,
the kernel delivers immediately and wakes it; otherwise the request waits
and the *next* `recv` picks the oldest (FIFO). `ipc_reply` finds the
request delivered to this server, stages the reply words (and optional
cap) into the parked call slot, and wakes the caller. The caller — resumed
inside its own `ipc_call`, on its own kernel stack, in its own address
space — copies the staged reply into its user buffer and returns. The
kernel never writes into a blocked thread's address space from another
thread's context; every user-memory touch happens in the owner's
context. That keeps CR3 reasoning trivial and SMAP honest.

The scheduler grows `State::Blocked`: `block_current()` = mark Blocked +
`plan_switch(false)` (the existing "do not re-enqueue current" path) +
switch; `wake(tid)` = Blocked→Ready + push to the ready ring. If a block
would leave **no** runnable thread, the machine halts with an explicit
`ipc deadlock` diagnostic — an honest crash, not a silent hang.

### Capability transfer

A transferred cap is a **copy** (never a move): the sender keeps its
original, the receiver gets an independent cap with exactly the source's
rights — attenuation-only, the ADR-0015 rule, enforced by reusing the
existing copy semantics (source must hold `COPY`). Placement is the
receiver's **first free slot** (v1 has no slot-addressed receive — the
M4.5 spawn protocol introduces explicit handle inheritance); the landing
slot index is reported in the message buffer's third word
(`u64::MAX` = no cap arrived). If the receiver's space is full the cap is
**dropped** and a `cap_drops` counter records it — dropping is safe
because v1 caps *describe*, never own (destroying or losing one frees
nothing); a later milestone with owning caps must revisit this (it is
listed in Consequences).

### Threads learn their process

`KThread` gains `proc_id` (0 = kernel thread) and the scheduler gains
`spawn_in_proc(name, entry, arg, pid)` (resolves the PML4 itself). The
dispatcher resolves the caller's cap space through `proc_id` — no global
names anywhere: a syscall finds its space exactly as §7 demands, through
the thread the kernel already knows.

### What the echo-server demo must prove (m4 test `ipc_echo`)

Two real process address spaces (`proc::create` ×2, hand-assembled
ring-3 payloads, per-thread CR3 via `spawn_in_proc`): the client
`ipc_call`s two pattern words and transfers a `Memory` cap; the server
`ipc_recv`s (blocks first — proving the parked-server path), echoes the
words via `ipc_reply`, then `notify`s a badge; the client checks the
echoed words **in ring 3**, `wait`s for the badge, and exits 42 only if
every step held. The kernel side independently asserts: dispatcher
counters exact, the transferred cap landed in the server's space with
source rights intact, the client's original cap untouched (copy, not
move), both exit statuses recorded, threads reaped, frames exact through
`proc::destroy`.

## Alternatives considered

1. **seL4-style endpoint objects with badge merging for sync IPC** — one
   object type serving both sync messages and badges. Powerful, but the
   merged-badge machinery (waiting-priority queues, badge words on
   messages) is a large surface for a first slice; §7 already separates
   the two roles, and separate objects keep each one's state machine
   small enough to test exhaustively in one milestone step.
2. **Long messages via kernel-copied user buffers** — rejected outright:
   it is exactly the "1 MiB kernel copy" §7 forbids; shared-memory
   channels (§7.3) are the sanctioned bulk path and stay a later step.
3. **Async-only messaging (mailbox queues, no blocking)** — would avoid
   the scheduler's Blocked state, but call/reply is the primary service
   pattern (§7.1) and a mailbox-only v1 would push queue management into
   every future server. Blocking is also the cheaper kernel: no polling.
4. **Slot-addressed cap receive (sender names the destination slot)** —
   more precise, but requires a per-message receive-slot contract and
   collision policy; first-free placement with a reported landing index
   is honest, bounded, and sufficient until M4.5's explicit inheritance.

## Consequences

**Gains:** the first two-process program in ArenaOS history; a scheduler
that can *wait* (the foundation for every future blocking operation —
FS, drivers, windows); typed, tested rendezvous with cap transfer under
the attenuation rule; five more frozen registry slots exercised from
ring 3.

**Costs / deferred (must be revisited, each named):**

- Shared-memory channels (§7.3) — bulk data still has no path by design.
- Priority donation ("caller donates its slice", §7.1) — moot under
  strict round-robin; becomes real when priorities exist.
- Multi-server endpoints, queued notification waiters, queue depth > 4 —
  all bounded-and-refused (`STATUS_BUSY`) rather than silently wrong.
- Cap *move* semantics and owning caps: the drop-on-full rule is only
  safe while caps describe rather than own.
- User-driven object creation and explicit handle inheritance — M4.5's
  root task and spawn protocol.
- The echo demo's payloads are hand-assembled (the m4 builder); turning
  the payload *crate* into an IPC participant waits for M4.6's shell
  work, when a real runtime (entry stub, syscall wrappers as a library)
  earns its keep.
