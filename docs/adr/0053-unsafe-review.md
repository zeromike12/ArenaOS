# ADR-0053 exact-source unsafe and build-path review (2026-09-30)

Scope: **the locked, serial-backend, x86_64-unknown-none verifier graph only**. This is a source/code-path review, not a formal proof of third-party correctness. No upstream crate was edited. All 23 archives and every extracted file are authenticated by `SOURCE-MANIFEST.tsv`; `FEATURE-TREE.txt` is the pinned target feature graph. A clean `--offline --locked --release --target x86_64-unknown-none --lib` build with an empty CARGO_HOME compiled 16 crates, not the 7 conditional alternatives. Recheck this review on any changed features, target flags, compiler version, dependency version or vendor hash. The dormant sources are pinned and their unsafe sites inventoried below, **not** claimed safe if activated.

## Unsafe-site inventory and disposition

The counts below are lexical occurrences of `unsafe {`, `unsafe fn`, `unsafe impl`, `unsafe trait` in published `src/*.rs`, excluding full-line comments. They include APIs compiled but never called. The reproducible **724-site, path/line/disposition** index is [`UNSAFE-SITES.tsv`](../../audit/phase84-crypto/UNSAFE-SITES.tsv), generated by `python3 tools/phase84_unsafe_sites.py`; it fails closed if the count drifts. Classification: 87 compiled runtime-source sites, 47 host-only, 34 backend/feature-excluded, 27 hardware-gated or other-arch SHA sites, 9 CPU-detection sites gated on no-OS/other architecture, and 520 sites in conditional lock-only crates. All noted files and source bytes are in the vendor tree, not hand-copied. The reviewer inspected each site's file and surrounding constructor/cfg/caller group, not merely grep counts. The count is a *completeness index*, not a claim that a grep can prove safety.

The unqualified scan of the 23 pinned crates totals 724 lexical unsafe sites (including 471 excluded `libc` sites); this ledger scopes every crate and each included file group. It does **not** assert that building source once or scanning for a keyword audits unreachable optional code as if it ran. No new dependency or change of Ed25519 arithmetic behavior was needed: explicit serial excludes unreachable SIMD code on the frozen no-OS target. Never use this audit to enable a different backend/arch, signing surface or `std`/alloc/serde features.

## Build scripts, proc macros, and source generation

Of five present build scripts, **only** `curve25519-dalek/build.rs` and `generic-array/build.rs` execute in the clean serial build. The former reads Cargo target cfg/rustc metadata and emits bits/backend/nightly flags; the latter asks `version_check` about Rust >=1.41 for a coherence cfg. Conditional `proc-macro2/build.rs` and `quote/build.rs` probe only local rustc version/features; `proc-macro2` writes only a temporary probe in Cargo OUT_DIR. Conditional `libc/build.rs` probes local rustc/target/OS environment (including FreeBSD/Emscripten command paths), emits cfg and never executes in this build. Source scan of all five scripts found no downloader, socket, runtime code-generation path or remote URL invocation; dependency resolution is forcibly offline, Cargo source replaced with the exact local vendor and the vendored tree is hash-checked. SIMD-only `curve25519-dalek-derive` proc macro and its host `syn`/`quote`/`proc-macro2` closure do not execute in this configuration. The guest verifier must not call a proc macro, dynamically generate executable bytes or fetch code.

## Validation / limitations

- `python3 tools/phase84_source_manifest.py | cmp - audit/phase84-crypto/SOURCE-MANIFEST.tsv`: every vendored file unchanged; `cargo tree --offline --locked --target x86_64-unknown-none -e features | cmp - FEATURE-TREE.txt` from the audit crate: exact feature closure.
- Fresh empty CARGO_HOME + source-vendored `cargo build --offline --locked --release --target x86_64-unknown-none --lib`: PASS; clean transcript `build/phase84-clean-audit.log` lists 16 compiled registry crates and **none** of the conditional five unsafe-bearing alternatives.
- Host RFC 8032, OpenSSL domains and malformed Ed25519 vectors pass; coverage-guided decoder fuzz findings are documented separately. These tests are differential behavior checks, not memory-safety proofs or proof of production-key security. Bare-metal runtime semantics must still be proven by QEMU guest refusals.
- Review applies only to exact version/hash/feature/target. The crate's default SIMD release codegen fails with compiler SIGILL on this sandbox; never silently remove the serial cfg. The new wrapper refuses weak and noncanonical public-key encodings; changing that check, `verify_strict` or signed domains invalidates acceptance.
