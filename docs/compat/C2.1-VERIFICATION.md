## 3. ABI and symbols (static)

| Check | Result |
|---|---|
| `run.py abi` | `checked 92 constants, mismatches=[]` |
| GCC and Clang archives: declared / defined in both | 110 / 110, missing 0, one-compiler-only 0 |
| GCC and Clang export the same supported symbol set | yes (`abi_symbol_agreement_gcc_clang=True`) |
| Test references (`c2_report.py`) | 78 host, 49 guest, 10 refused by design, 1 with no reference (`tss_delete`, a documented no-op) |
| C2.1 added or removed symbols | none (C2.1 is a correction, not an API expansion) |

Undefined symbols in app ELFs (`nm -u`, from the receipt):

- GCC app ELFs: none.
- Clang app ELFs (C2 console, xxHash, C1 native): one **weak undefined** reference,
  `arena_legacy_write` (`w`).

Root cause (found after the sweep, from the same sources; no runtime code changed):
`src/rt.c` `arena_write` takes the address of the weak prototype declared in `src/internal.h`
and calls it behind `arena_legacy_serial_active && arena_legacy_write != NULL`. The reference is
present in `rt.o` under **both** compilers. Checked with Zig 0.17.0 clang and the system gcc,
with `nm` and `readelf -r`: Clang emits `R_X86_64_32` and `R_X86_64_PLT32`; GCC emits
`R_X86_64_GOTPCREL` and `R_X86_64_PLT32`. GCC's final app ELFs drop the symbol at link time.
Why the link differs is **not established**. The flag is set only by `arena_legacy_serial_enable`
(`legacy_debug.c`), and no ordinary image sets it, so the call is unreachable there. The comment in
`src/rt.c` that says ordinary images "never reference arena_legacy_write" is **wrong for both
compilers**. It is left unchanged in C2.1 because a source edit would change the evidence tree
and require full re-qualification.

Ordinary applications do not set the flag and do not define the sink. The harness
(`guest_c2.py`, the `arena_legacy_write` check) refuses a **defined** or **strongly referenced**
legacy symbol and allows the weak undefined reference.

Proposed fix (not applied; needs a source change and the full sweep): move the dispatch into
`legacy_debug.c`, so `rt.o` carries no reference to the weak symbol. The legacy file would register
a hook through a non-weak pointer when it is enabled.

## 9. Open items and flakes (reported, not resolved)

1. **C1 native GCC, one transient failure at `c8887a1`.** Run 4 timed out at
   "All Applications did not launch the native package" (the GUI search-and-launch wait,
   `tools/test_m10_apps.py:61` via `guest_native.py:271`). The C1 result line
   `[c-native] RESULT PASS groups=9/9 checks=93` had already printed in that run's serial log.
   The same GCC suite passed 5/5 at `9c93f8c`, and the Clang suite passed 5/5 there too. The cause is
   not established. It is one occurrence in 10 GCC runs across two sweeps. Treat it as a transient
   launch-step flake under investigation, not a runtime result. Do not claim the launch step is
   flake-free.
2. **Clang weak undefined `arena_legacy_write`** (section 3). Root cause found (`rt.o` carries the
   reference under both compilers). The `rt.c` comment is wrong. Fix proposed, not applied.
3. **`getchar` on a live stdin** is untested (no controlled input fixture).
4. **`tss_delete`** has no test (a documented no-op; no key can exist).
5. **`cnd_timedwait` deadlines use the monotonic base.** C11 specifies `TIME_UTC`. No wall-clock
   grant exists, so this is a documented deviation.
6. **The C2.1 harness changes are judged by a self-test,** not by a second independent runner.
7. **Kernel and ABI:** no change. C2.1 adds no syscall, capability type, ARST field, or kernel
   path. ADR-0111 stays **Proposed**, and its pinned regression test still reproduces the defect.

## 10. What is not claimed

- No production 100/100 claim. No production kernel or ABI change. No SDL3 port or build.
- No general floating point, SIMD, or FP state. The no-FP profile is enforced by the audit, not by the
  flags alone.
- No full libc, POSIX, pthreads, or upstream SDL3 compatibility. The host ASan and UBSan results are not
  kernel memory-safety proof.
- No graphical guest run. B-GFX-1 is blocked (`C2.1-B-GFX-1-HANDOFF.md`).
