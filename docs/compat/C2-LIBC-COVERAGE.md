# C2 libc and threads: coverage

Status: EXPERIMENTAL. This is a bounded native C subset for ArenaOS. It is not a
full C library, not POSIX, and not a Linux or glibc compatibility layer.

Machine-readable source: `experiments/c-runtime/compat/c2-compat-report.json`,
generated by `experiments/c-runtime/c2_report.py` from the built archives and the
test sources.

## Evidence classes

| Class | Meaning |
|---|---|
| **defined** | The name is exported by `build/guest-{gcc,clang}/lib/libarena_c.a` (checked with `nm`). Header presence alone is not counted. |
| **host** | Referenced by a host ASan+UBSan test (`host/test_libc.c`, `host/test_runtime.c`), often against glibc as a reference. Host-only evidence. |
| **guest** | Referenced by a guest app and asserted by an App A group that passed in an exact-PASS QEMU run. Execution evidence is the run receipt, not the reference. |
| **refused** | Declared, but deliberately returns an error (or a quiet NULL) with `errno` set where applicable. Listed below. |
| **untested** | Defined, but no host or guest test references it. Not claimed. |

The report's reference counts are source references only. The report strips
comments, string literals, and `#include` lines before matching, so prose such as
"G4 time" does not count as a call to `time()`. (An earlier revision counted prose
and overstated coverage; that has been fixed.) Execution is shown only by the
exact-PASS runs listed in `docs/compat/C2-FINAL-REPORT.md`.

## Memory (`stdlib.h`)

- `malloc`, `calloc`, `realloc`, `free` use the C1 VM allocator. No second allocator.
- `aligned_alloc`: power-of-two alignment. `align <= 16` uses the normal path.
  `32 <= align <= 65536` uses validated aligned blocks. Larger, or non-power-of-two,
  is refused with NULL and `errno`: `EINVAL` for a bad alignment, `ENOMEM` otherwise.
- `calloc` overflow and allocation refusal set `ENOMEM`. `realloc` failure leaves the
  original block untouched.
- Invalid frees are refused and counted. They never reach memory outside the heap.
- Tested: host (alignment, overflow, invalid free, realloc failure). Guest: App A
  group G3 (`malloc`, `calloc`, `realloc`, `free`, `aligned_alloc`, accounting).

## Strings and memory (`string.h`)

`memcpy memmove memset memcmp memchr strlen strnlen strcmp strncmp strcoll strcpy
strncpy strcat strncat strchr strrchr strstr strpbrk strspn strcspn strtok strerror`.

- Standard semantics, tested on the host (most against glibc).
- `strcoll` in the C locale only.
- Guest: `strlen`, `strcmp`, `memcpy`, `memset` are used by App A; no separate
  guest assertion covers the rest of this group.

## Numeric conversion and integer math (`stdlib.h`)

`atoi atol atoll strtol strtoul strtoll strtoull labs llabs div ldiv lldiv rand srand qsort bsearch getenv`.

- `strtol` family: differential tests against glibc (host).
- `div`, `ldiv`, `lldiv`: defined in C2.6 (they were declared but **not defined** before
  that, found by `c2_report.py`). Truncation toward zero is tested on the host. Division
  by zero returns zeros; it does not trap. The standard leaves this undefined.
- `rand` and `srand`: a deterministic generator, repeatable for a given seed. It is
  not cryptographic. Host-tested only.
- `getenv`: reads only the environment carried by the verified ARST record (`envp`).
  Returns NULL when no record is present. Host-tested only.
- Host-only: `atoi`, `atol`, `atoll`, `labs`, `llabs`, `bsearch`, `qsort`.

## Formatted output (`stdio.h`)

`printf vprintf fprintf vfprintf sprintf snprintf vsprintf vsnprintf puts putchar fputs`.

- Bounded output. `snprintf` returns the length that would have been written, even
  when truncated. This follows C11.
- Partial-write handling: a short write is retried. A write error is returned as
  `-1` with `errno`.
- Supported conversions: `d i u x X o c s %` with flags, width, and precision.
  Differential against glibc on the host for the supported set.
- **Refused, with no output written**: floating point (`f F e E g G a A`, and
  `long double`) returns `-1`, `errno = ENOTSUP`. This avoids silently incorrect
  float formatting. `%n` is refused with `EINVAL`.
- Unknown conversions and a trailing `%` are echoed, as in C1 (pinned by the C1 contract).
- `%p` with NULL prints `(nil)`. C1 printed `0x0`. This is a deliberate change.
- `vprintf`, `vfprintf`, `vsprintf`, `vsnprintf`: host-tested through real `va_list`
  wrappers (test code in `host/test_libc.c`). Not used by any guest app.
- Guest: App A group G1 (`puts`, `fputs`, `printf`, `snprintf`, `putchar`, and the
  refusal path).

## Streams (`stdio.h`)

- `stdin`, `stdout`, `stderr` are granted through the ARST stream set. They are not
  ambient filesystem authority.
- Missing grant: `ARENA_E_NO_STREAMS` (App A's negative build exits `58`).
- `fputc putc fwrite`: **guest** (App A G7). `fputs puts` guest-tested in G1.
- `feof ferror clearerr setvbuf`: **guest** (App A G7, asserted). `setvbuf` accepts modes 0–2
  and rejects others with `EINVAL`; the buffer and size arguments are ignored.
  `perror`: called in G7; its output appears in the log, not asserted.
- `fgetc getc fgets fread`: **host-tested for the refusal path only** (NULL stream
  gives EOF, NULL, or 0 with `EBADF`). A read from a live stdin is not tested in the
  guest: an idle stdin blocks, so the guest suite uses `arena_stream_read_some` and
  does not call the blocking `FILE` reads.
- `getchar`: **no test reference**. It is the blocking form of `fgetc` on stdin.
- `fflush`: host-only.
- `fclose`: **host-tested for the refusal**: NULL or a closed stream returns `-1` with
  `EBADF`. Closing a granted endpoint is not tested. `fclose` is not refused by design.
- `fopen freopen remove rename`: **refused** with `ENOSYS` (`fopen` and `freopen` may
  also return NULL). No file authority exists in C2. Host-tested as refusals. Standard
  streams are not a file system. Using files would need a broker interface that does
  not exist yet (see the blocker list in `C2-FINAL-REPORT.md`).

## Time (`time.h`)

- `clock_gettime(CLOCK_MONOTONIC)`: implemented over the existing ArenaOS time service.
  Guest-tested (App A G4).
- `nanosleep`: guest-tested (App A G4, 2 ms, with the monotonic clock advancing by at
  least 2 ms).
- `CLOCK_REALTIME`: **refused** with `ENOSYS` (no wall-clock grant). Guest-tested (G4).
- `time()`: **refused** with `ENOSYS`, returns `-1`. **No test reference.**
- `clock()`: **refused** with `ENOSYS`, returns `-1`. No CPU accounting is exposed.
  **No test reference.**
- `time()` and `clock()` cannot be linked into the host test: `src/libc_time.c` is not
  in the host build list. Their refusal is established by source inspection only. This is
  recorded as remaining work; it is not claimed as tested.

## Errors and exit (`errno.h`, `stdlib.h`, `assert.h`)

- `errno` is `_Thread_local`, so each thread has its own value. The macro expands to
  `__arena_errno_location()`. That function is host-tested directly, and every guest
  test reads `errno` through it.
- `exit`: runs the atexit handlers in reverse registration order (up to 32), flushes
  `stdout` and `stderr`, closes fds 1 and 2, then ends with the given status. Host-tested
  (ordering). Guest-tested (App A G9): the atexit line is printed after the RESULT line.
- `_Exit`: ends immediately with the given status and runs no handlers. Host-tested
  (forked child exits with status 7).
- `abort`: ends with status 134 and runs no handlers. Host-tested (forked child, status 134).
- `__arena_assert_fail`: prints the assertion and calls `abort`. Host-tested (forked
  child, status 134).
- Guest coverage of `_Exit`, `abort`, and `assert` failure: none. Those paths are host
  evidence only.

## Threads (`threads.h`): C11 subset

Implemented as thin bindings over `SYS_THREAD_*` and `SYS_SYNC_*`. This is not pthreads.

| Function | Status | Evidence |
|---|---|---|
| `thrd_create`, `thrd_join` | implemented | guest (App A G5, C1 native) |
| `thrd_yield` | implemented | called by App A G5; not asserted |
| `thrd_detach` | implemented | guest (App A G6). See the detach caveat below. |
| `thrd_exit` | implemented | **no test reference** |
| `thrd_current`, `thrd_equal` | implemented | guest (App A G6) |
| `thrd_sleep` | implemented over `nanosleep` | guest (App A G6, 1 ms) |
| `mtx_init` (plain), `mtx_lock`, `mtx_unlock` | implemented | guest (G5) |
| `mtx_trylock` | implemented | guest (G6): free succeeds, self-held returns `thrd_busy` |
| `mtx_destroy` | implemented | called in G6; not asserted |
| `mtx_timedlock` | **refused**, `thrd_error` | guest (G6) |
| recursive mutexes (`mtx_recursive`) | **refused** at `mtx_init` | guest (G6) |
| `cnd_init`, `cnd_timedwait` | implemented | guest (G5, timeout case) |
| `cnd_wait`, `cnd_broadcast` | implemented | guest (G6): a waiter parked on `cnd_wait` is woken by `cnd_broadcast` and returns its status |
| `cnd_signal` | implemented | guest (G6, no waiters: succeeds) |
| `cnd_destroy` | implemented | called in G6; not asserted |
| `call_once` | implemented | guest (G5) |
| `tss_create`, `tss_set` | **refused** (`thrd_error`) | guest (G6) |
| `tss_get` | **refused**, returns `NULL` (no value) | guest (G6) |
| `tss_delete` | no-op (no key table exists) | **no test reference** |

Rules that apply:

- Refused operations return an error. None returns a fake success.
- `tss_get` returning `NULL` is a quiet refusal, not an error code. C11 defines `NULL`
  as "no value". This is a known deviation; applications must not rely on `tss_get`
  to detect support. Use `tss_create` (which refuses) as the feature test.
- Thread stacks and quota come from the kernel (4 user threads per process).
- Process exit status is the status of the last thread to exit (C1 rule). See the
  detach caveat below.
- Thread-local storage (`_Thread_local`) is isolated per thread. Tested by C1 native
  group T8 on both compilers. C2 App A does not exercise TLS directly.

### Known caveats in App A's thread test (documented; not fixed in this evidence set)

- **Detach and exit status.** G6 creates a detached thread that sets a flag and returns.
  The main thread waits on the flag with a bounded sleep loop, then continues. The flag
  is set before that thread has finished exiting, so if the detached thread's exit landed
  after main's exit, the last-thread rule could change the process status. In the C2 guest
  runs at the source commit `7b27c67` (5 gcc and 5 clang runs), App A's exit status was
  61 in every run. That is observation, not a proof. There is no join-free way in the current runtime to observe
  a detached thread's termination. This is recorded as remaining work.
- **Uninitialized key read.** G6 calls `tss_get(key)` on a `tss_t` whose `tss_create`
  call was refused, so the key is never initialized. The call is harmless, but it passes
  an indeterminate value. The fix is an initializer on the key. This is recorded as
  remaining work for the next App A change.

## Symbols with no test reference (5)

`clock`, `time`, `getchar`, `thrd_exit`, `tss_delete`. Of these, `clock` and `time`
are refused by design (source inspection only). The others are implemented but
unverified. `getchar` is blocked by the idle stdin in the guest, and the host build
has no stdin fixture. Closing these is recorded as remaining work in the final report.

## Not provided (explicit)

- No `pthread_*` (C2 does not fake pthreads).
- No `setjmp`/`longjmp`: `setjmp.h` does not exist in the SDK headers, and none is provided.
- No locale support beyond the C locale.
- No dynamic loading (`dlopen`), no `signal`, no `fork`/`exec`. (`fork` appears only
  in the host test harness, not in the C2 library.)
- No floating-point formatting or conversion (see Formatted output).
- No file system and no `opendir`/`readdir`.
- `getenv` reads only the environment carried by the verified ARST record (`envp`).
