## 2. Linker Symbol Ownership and Dead-Code Elimination Analysis

### 2.1 The `_exit` Symbol Resolution Investigation

During architectural review, Finding D noted:
> "The generated linker report also claims `_exit` is provided by compatibility glue, but the final linked symbol inventory does not contain `_exit`. Determine whether this is normal dead-code elimination or a documentation error."

To investigate this, we analyzed `experimental/upstream-sdl3/build_c2/sdl3_upstream_c2.map` and the compilation pipeline:

1. **Source Definition in `arenaos_c2_glue.c`:**
   ```c
   #include <stdlib.h>
   /* Resolve POSIX _exit to standard C _Exit provided by libarena_c.a */
   void _exit(int status) {
       _Exit(status);
   }
   ```
   This translation unit is compiled with `-ffunction-sections -fdata-sections`, creating an individual ELF input section named `.text._exit`.

2. **Callers in Upstream SDL3:**
   In genuine upstream SDL 3.2.0 (`SDL.c`), the only function that invokes `_exit` is `SDL_ExitProcess(int exitcode)`:
   ```c
   extern SDL_NORETURN void SDL_ExitProcess(int exitcode);
   SDL_NORETURN void SDL_ExitProcess(int exitcode) {
   #if defined(HAVE__EXIT)
       _Exit(exitcode);
   #else
       _exit(exitcode);
   #endif
   }
   ```
   `SDL_ExitProcess` is called exclusively in internal panic handlers (`SDL_assert.c`, `SDL_hashtable.c`, `SDL_dynapi.c`). It is **never** invoked during normal application startup, presentation, event polling, or clean shutdown.

3. **Linker Pass (`-Wl,--gc-sections`):**
   When `demo_main.c` returns 0 from `main()`, control returns to `crt0.o`:
   ```c
   arena_libc_exit(rc);
   ```
   `arena_libc_exit` executes exit handlers and invokes `arena_exit(status)` (`SYS_EXIT`).
   Because `demo_main.c` does not trigger assertions or fatal internal panics:
   - `SDL_ExitProcess` is unreferenced.
   - The linker marks `.text.SDL_ExitProcess` for garbage collection.
   - Because `SDL_ExitProcess` is discarded, `_exit` has zero incoming references.
   - The linker marks `.text._exit` in `arenaos_c2_glue.o` for garbage collection.

4. **Linker Map Confirmation (`sdl3_upstream_c2.map`):**
   ```
   Discarded input sections
   ...
    .text._exit    0x0000000000000000        0x6 /home/user/ArenaOS/experimental/upstream-sdl3/build_c2/arenaos_c2_glue.o
   ...
    .text.SDL_ExitProcess
                   0x0000000000000000        0x6 /home/user/ArenaOS/experimental/upstream-sdl3/build_c2/libSDL3_upstream_c2.a(SDL.o)
   ```

**Conclusion:** The absence of `_exit` in the final linked ELF symbol table is **completely normal and expected dead-code elimination by GNU ld `--gc-sections`**. The compatibility glue successfully satisfies any potential link-time reference without bloating the final executable payload.

## 3. Subsystem Symbol Ownership Inventory

- `main`: Application entry point called by `crt0.o`.

- `SDL_Init`, `SDL_Quit`: Upstream subsystem initialization and teardown.
- `SDL_CreateWindow`, `SDL_CreateWindowWithProperties`: Upstream window management.

- `adsk_disconnect`: Window destroy notification and shared memory unmapping.
- `adsk_poll_event`: Desktop event polling via ADSK-v1 protocol.
- `adsk_sleep_ms`: Direct hardware timer wait via `SYS_TIMER_ARM` and `SYS_WAIT`.

### 3.4 Shared C Runtime (`crt0.o` + `libarena_c.a`)

- `arena_startup`, `arena_startup_gate`: ARST v2 canonical startup parser.
- `malloc`, `free`, `calloc`, `realloc`: Shared buddy memory allocator (`alloc.o`).
- `memcpy`, `memmove`, `memset`: Standard C memory operations (`libc_names.o`).
- `_Exit`, `exit`: C11 standard process termination (`exit.o`).
- `arena_vm_reserve`, `arena_vm_commit`: Dynamic virtual heap memory management (`vm.o`).

## 4. Memory Budget Differentiation

| Memory Dimension | Configured Ceiling | Target C2 Utilization | Headroom | Verification Status |
|---|---|---|---|---|
| **Kernel Image File Size** | 256 KiB (262,144 B) | 243,120 B | 19,024 B | **CONFORMS** |
| **Kernel PT_LOAD Pages** | 128 pages (512 KiB) | 50 pages | 78 pages | **CONFORMS** |
| **Dynamic Virtual Heap** | 16 MiB (4,096 pages) | Lazy reservation | 16 MiB available | **CONFORMS** |

The 256 KiB / 128-page image loader budget restricts only the executable's static `PT_LOAD` segments at process spawn time. The 16 MiB virtual heap is reserved lazily via `SYS_VM_RESERVE` (32) and committed on demand in 64 KiB chunks via `SYS_VM_COMMIT` (33), providing ample dynamic memory for SDL3 surfaces without violating kernel image limits.
