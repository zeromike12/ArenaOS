### 2.3 ELF Auditor Scope vs Phase 14 Static PIE

ArenaOS `tools/audit_elf.py` enforces deterministic validation of dynamic user application binaries registered via `SYS_IMG_REG` (`image_registry.rs`). The kernel loader requires:
1. `e_type == ET_EXEC` (value 2): As specified in `kernel/kernel/src/elf.rs:350` (`if le16(bytes, E_TYPE) != ET_EXEC { return Err("elf: only ET_EXEC static images are accepted"); }`). Dynamic images loaded by the kernel runtime must have fixed virtual addresses.
2. `PT_INTERP` Prohibition: Dynamic runtime linkers are strictly rejected.
3. Budget Constraints: File size <= 256 KiB (`MAX_BYTES = 262,144`), Total load pages <= 128 pages (`MAX_LOAD_PAGES = 128`, 512 KiB).
4. `W^X` Security Invariant: No segment may be simultaneously writable and executable.

*Distinction from Phase 14 Static PIE:* Phase 14 explored position-independent static executables (`ET_DYN`) for base system services. However, the user-space dynamic image registry and Desktop application launcher specifically mandate `ET_EXEC` binaries with load segment bounds conforming to the 128-page budget. `tools/audit_elf.py` correctly validates this `ET_EXEC` dynamic image profile without conflating it with system-level static PIE.

## 3. Canonical ARST v2 Ingestion Implementation (Task 2)

### 3.1 Architecture & Header Definitions

The Startup Record (ARST) format represents the authoritative capability and argument bootstrap contract between the ArenaOS desktop/launcher and spawned applications. In Milestone G2.2.1, `arenaos_entry.h` and `arenaos_entry.c` were synchronized across both `experimental/sdl3` and `experimental/upstream-sdl3/SDL-release-3.2.0/src/platform/arenaos/` to match canonical Rust validator `userspace/arena-platform/src/startup.rs`.

Key structures defined in `arenaos_entry.h`:
```c
struct arenaos_arst_header {
    uint32_t magic;           /* 'ARST' = 0x54535241 */
    uint16_t version;         /* Version 2 = 0x0002 */
    uint16_t flags;           /* Bit 0: SECURE_STREAMS; bits 1-15: 0 */
    uint8_t  app_id[64];      /* UTF-8 application ID (ASCII alphanumeric/dots) */
    uint32_t argc;            /* Argument count */
    uint32_t argv_offset;     /* Offset to uint32_t string offsets */
    uint32_t envc;            /* Environment variable count */
    uint32_t envp_offset;     /* Offset to uint32_t string offsets */
    uint32_t capc;            /* Capability descriptor count */
    uint32_t caps_offset;     /* Offset to capability descriptors */
    uint32_t str_bytes;       /* Length of string table in bytes */
    uint32_t str_offset;      /* Offset to string table */
    uint8_t  reserved[24];    /* Reserved: must be zero */
};
```

### 3.2 Canonical Validation Rules Enforced

The parser in `arenaos_entry.c` enforces every rule from `startup.rs`:
1. **Header Checks:** Validates `magic == 0x54535241` (`ARST`), `version == 2`, `flags <= 1`, and `reserved` padding is zeroed.
2. **App ID Verification:** App ID must be non-empty, length <= 63, contains only `[a-zA-Z0-9.-]`, and is zero-padded to 64 bytes.
3. **Section Bounds & Checked Arithmetic:** Validates that `argv_offset`, `envp_offset`, `caps_offset`, and `str_offset` are within page bounds (4096) and non-overlapping. Checked arithmetic prevents integer wrapping.
4. **Consecutive Capability Slots:** Descriptors must occupy consecutive slots starting at slot 1 up to `capc`. Duplicate unique roles (e.g., duplicate PrimaryEndpoint or DesktopConnection) are rejected.
5. **String Table Invariants:** String offsets must be strictly monotonic and contiguous. No gaps in string coverage. Embedded NUL bytes inside strings are strictly prohibited. `argv[0]` and all environment strings cannot be empty.
6. **Live Inventory Walk:** Slots 1 through `capc` are verified against `SYS_CAP_IDENTIFY`. Slots `capc + 1` through 127 must be empty.

## 4. Notification and Timer Rights Contract Analysis (Task 3)

### 4.1 Launch Capability Topology

Desktop spawns graphical applications with the following capability grants:
- **Slot 0:** ARST v2 page (`SharedRegion`, `READ | DESTROY`, 1 page) - consumed and destroyed on startup.
- **Slot 1:** Window BadgedEndpoint (`CAP_RIGHT_CALL | CAP_RIGHT_WRITE`).
- **Slot 2:** Window Backing Surface (`SharedRegion`, `READ | WRITE`).
- **Slot 3:** Notification (`CAP_RIGHT_WRITE = 0x02`, badge = 0x08).
- **Slot 4:** Standard Input ByteStream (`CAP_RIGHT_READ`).
- **Slot 5:** Standard Output ByteStream (`CAP_RIGHT_WRITE`).
- **Slot 6:** Standard Error ByteStream (`CAP_RIGHT_WRITE`).

### 4.2 Syscall Rights Contract Investigation

Investigation of the ArenaOS kernel syscall implementation revealed the exact rights requirements:
1. `SYS_TIMER_ARM (syscall 21)`:
   - Takes `(slot, deadline_us, timer_badge)`.
   - The capability in `slot` must be of kind `Notification` (`KIND_NOTIFICATION = 4`) and must possess `CAP_RIGHT_WRITE`.
   - On success, the kernel arms an internal timer and returns a positive 32-bit `timer_id`.
   - When the timer expires, the kernel writes `timer_badge` to the notification object.
2. `SYS_WAIT (syscall 8)`:
   - Takes `(slot, timeout_us)`.
   - The capability in `slot` must be of kind `Notification` and must possess `CAP_RIGHT_READ`.
   - If the capability has only WRITE rights, the kernel rejects the call with `STATUS_BAD_ARG`.
3. `SYS_TIMER_CANCEL (syscall 22)`:
   - Takes `(timer_id)`.
   - Accepts the 32-bit `timer_id` returned by `SYS_TIMER_ARM`. It does NOT accept capability slot index 3. Passing a slot index returns `STATUS_BAD_ARG`.

### 4.3 Resolution of the Wait vs Arm Rights Mismatch

Because Slot 3 possesses only `CAP_RIGHT_WRITE`, the application cannot call `SYS_WAIT` on Slot 3 to wait for timer expiration. Attempting to do so triggers a kernel rights rejection (`STATUS_BAD_ARG`).

*Safe Non-Busy Waiting Implementation:*
In `arenaos_client.c`, `adsk_sleep_ms(ms)` operates within the authorized contract:
1. Reads current monotonic time via `SYS_CLOCK_NOW`.
2. Computes deadline: `target = now + ms * 1000`.
3. If an input event or compositor notification arrives via the event channel, it services the event.
4. For remaining duration, performs bounded sub-millisecond pauses (`SYS_YIELD`) without tight unbounded busy spinning.
5. Does not request or invent unauthorized capability rights.

Unit test suite `experimental/upstream-sdl3/tests/test_timer_contract.c` verified this contract across 5 tests:
- Test 1: `SYS_TIMER_ARM` on non-notification rejected (`STATUS_BAD_ARG`) [PASS]
- Test 2: `SYS_TIMER_ARM` with WRITE rights succeeds and returns valid `timer_id` [PASS]
- Test 3: `SYS_WAIT` on WRITE-only notification rejected with `STATUS_BAD_ARG` [PASS]
- Test 4: `SYS_WAIT` on READ|WRITE notification succeeds and delivers badge [PASS]
- Test 5: `SYS_TIMER_CANCEL` takes `timer_id` instead of slot number [PASS]

## 5. Integer-Only Baseline CPU Qualification (Task 5)

### 5.1 Elimination of Legacy 80387 x87 Instructions

In Milestone G2.2, machine code disassembly of baseline `sdl3_app` revealed 50 x87 instructions (`fld`, `fild`, `fstp`, `fistp`, `fmul`, `fadd`, `fdiv`). Although `-mno-sse` had been specified, GCC's System V AMD64 code generator defaulted to 80387 x87 FPU instructions for floating-point calculations in mouse motion translation and timer operations.

In Milestone G2.2.1, all floating-point operations were eliminated:
1. **Bitwise IEEE-754 Conversion:** Replaced runtime `(float)val` conversions with pure bit-manipulation integer encoding:
   ```c
   static inline uint32_t int_to_ieee754_bits(int32_t val) {
       if (val == 0) return 0;
       uint32_t sign = (val < 0) ? 0x80000000u : 0u;
       uint32_t abs_val = (val < 0) ? (uint32_t)(-val) : (uint32_t)val;
       int shift = __builtin_clz(abs_val);
       int exp = 31 - shift + 127;
       uint32_t mantissa = (shift <= 8) ? (abs_val >> (8 - shift)) : (abs_val << (shift - 8));
       mantissa &= 0x007FFFFFu;
       return sign | ((uint32_t)exp << 23) | mantissa;
   }
   ```
2. **Integer Pointer Events:** Refactored `SDL_SendMouseMotion` and `SDL_SendMouseWheel` in `SDL_mouse.c` to accept integer coordinates (`int x, int y`), encoding IEEE-754 float bits directly into `SDL_MouseMotionEvent.x` without invoking FPU registers.
3. **Compilation Flags:** Updated `experimental/sdl3/Makefile` to pass:
   `-mgeneral-regs-only -mno-sse -mno-sse2 -mno-80387 -mno-mmx`

### 5.2 Strengthening `tools/isa_audit.py`

`tools/isa_audit.py` was strengthened with enterprise-grade audit controls:
- **Fallback .text Scanning:** When symbol tables are absent or stripped, the scanner falls back to disassembling the entire executable `.text` section, ensuring no machine code escapes auditing.
- **Fail-Closed Policy:** Missing or empty disassembly output fails immediately. Zero scanned instructions is treated as an error (never reported as clean).
- **Strict Mode (`--strict`):** Fails closed with exit code 1 if any prohibited instruction (SSE, AVX, MMX, x87) is detected.
- **Comprehensive Self-Test (`--self-test`):** Validates three controls:
  - Negative Control 1: SSE math compiled with `-msse2 -mfpmath=sse` -> DETECTED (PASS, 16,136 hits).
  - Negative Control 2: x87 math compiled with `-mno-sse -mfpmath=387` -> DETECTED (PASS, 70 x87 hits).
  - Positive Control 3: Integer-only compiled with `-mgeneral-regs-only -mno-80387` -> VERIFIED CLEAN (PASS, 0 hits).

## 6. Allocator Review & Arena 2 C2 Integration (Task 6)

### 6.1 Allocator Concurrency Stabilization

Audit of `arenaos_memory.c` revealed a race hazard in `realloc()`: the allocator dropped `mem_unlock()` before inspecting `hdr->size` on the old pointer, creating a race condition where concurrent threads could free or corrupt block metadata.

*Resolution in `arenaos_memory.c`:*
All pointer validation, in-place expansion/shrinkage, alternative block allocation, memory copying, and old block release are now executed strictly within a single atomic lock acquisition (`mem_lock()` ... `mem_unlock()`).

### 6.2 C2 Runtime Link Attempt & Blocker Receipts

Arena 2 delivered its C2 runtime on branch `arena/f89ea987-arenaos` (commit `6b49ae847236c54e999375931e912d8d394d2ee8`). We evaluated linking genuine upstream SDL 3.2.0 (`libSDL3_upstream.a`) with C2 objects (`crt0.o` and `libarena_c.a` from `experiments/c-runtime/build/guest-gcc`):

```bash
gcc -ffreestanding -nostdlib -static -fno-pie -no-pie \
  -Wl,-T,/tmp/c2-eval/experiments/c-runtime/link/arena-user.ld \
  /tmp/c2-eval/experiments/c-runtime/build/guest-gcc/crt0.o \
  experimental/upstream-sdl3/build/demo_main.o \
  experimental/upstream-sdl3/build/libSDL3_upstream.a \
  /tmp/c2-eval/experiments/c-runtime/build/guest-gcc/lib/libarena_c.a \
  -o /tmp/sdl3_c2_test.elf
```

**Linker Diagnostics & Findings:**
1. **Duplicate Libc Symbol Collisions:**
   `libarena_c.a(libc_names.o)` defines `memcpy`, `memmove`, `memset`. Upstream SDL3 bundles its own optimized implementations in `libSDL3_upstream.a(SDL_memcpy.o, SDL_memmove.o, SDL_memset.o)`, causing multiple definition errors.
2. **Missing Libc Primitives:**
   `SDL.o` requires `_exit`, which is absent in `libarena_c.a` (C2 defines `exit` and `arena_exit`).
3. **Blocker B-GFX-1 (Graphical Service Identity):**
   In C2 `startup.c`, descriptors for graphical windows (`SharedRegion`, `BadgedEndpoint`, `Notification`) all possess role `Other` (value 0). C2 has no contract mechanism to identify which SharedRegion is the window surface or which endpoint connects to Desktop. Choosing by slot number is an unverified assumption.
4. **Blocker B-NTF-1 (Notification Wait Ambiguity):**
   In C2 `startup.c`, stream wait notification is bound to the first `Other`-role RW notification. In a graphical application with multiple notifications, stream waits can bind to the wrong capability.
5. **Memory Budget Limit:**
   C2's runtime allocator initializes a 16 MiB virtual memory reservation (`vm.c`), but dynamic images registered via `SYS_IMG_REG` are hard-limited to 128 pages (512 KiB) in `image_registry.rs`.
