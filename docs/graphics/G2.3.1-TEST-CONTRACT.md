## 1. Authoritative Observable Log Contract

To eliminate test fragility and maintain strict synchronization between guest application code and host qualification harnesses, this specification defines the **authoritative observable log contract** for native SDL3 applications on ArenaOS.

### 1.1 Baseline Observable Event Markers

The table below specifies every observable event required for qualification of Target A (`sdl3_app`):

| Sequence Index | Event Name | Emitting Component | Authoritative Log String Format / Match Pattern | Meaning & System Invariant |
|---|---|---|---|---|
| **E01** | Desktop Ready | `userspace/desktop` | `[desktop] real desktop frame presented` | Compositor initialized and presenting first desktop frame. |
| **E02** | Desktop Enum | `userspace/desktop` | `[desktop] desktop surface shows /Users/user/Desktop` | Desktop directory enumerated and ready for pointer input. |
| **E03** | APB1 Install | `userspace/desktop` | `[desktop] APB1 installed; signed version=1 (no launch authority implied)` | APB1 bundle signature verified and payload installed to AFS2. |
| **E04** | Video Init | `experimental/sdl3` | `[sdl3-app] SDL3 video subsystem initialized successfully!` | `SDL_Init(SDL_INIT_VIDEO)` completed successfully. |
| **E05** | Window Created | `experimental/sdl3` | `[sdl3-app] SDL_Window created:` | Window structure allocated and assigned window ID. |
| **E06** | Surface Acquired | `experimental/sdl3` | `[sdl3-app] Surface acquired:` | ADSK-v1 client mapped surface buffer via `SYS_SHARED_MAP`. |
| **E07** | Loop Entered | `sdl3-app/main.c` | `[sdl3-app] Entering interactive frame loop` | Main event loop entered for animation frames. |
| **E08** | Milestone 0 | `sdl3-app/main.c` | `[sdl3-app] Frame milestone reached: frame=0; damage published (box at %d,%d, color=%d)` | Initial frame rendered and ADSK-v1 damage published. |
| **E09** | Milestone 25 | `sdl3-app/main.c` | `[sdl3-app] Frame milestone reached: frame=25; damage published (box at %d,%d, color=%d)` | Animation running smoothly before interactive input. |
| **E10** | Mouse Button Down | `sdl3-app/main.c` | `[sdl3-app] Event: Mouse button down at (%d, %d) -> state transition color=%d` | Mouse click delivered from Desktop broker and state mutated. |
| **E11** | Spacebar Press | `sdl3-app/main.c` | `[sdl3-app] Event: Spacebar pressed -> state transition color=%d` | Keyboard event delivered from broker and state mutated. |
| **E12** | Milestone 60 | `sdl3-app/main.c` | `[sdl3-app] Frame milestone reached: frame=60; damage published (box at %d,%d, color=%d)` | Frame rendering continuing normally after input events. |
| **E13** | Milestone 90 | `sdl3-app/main.c` | `[sdl3-app] Frame milestone reached: frame=90; damage published (box at %d,%d, color=%d)` | Multi-frame visual continuity verified past midpoint. |
| **E14** | Milestone 119 | `sdl3-app/main.c` | `[sdl3-app] Frame milestone reached: frame=119; damage published (box at %d,%d, color=%d)` | Final animation frame rendered; loop termination imminent. |
| **E15** | Clean Exit | `sdl3-app/main.c` | `[sdl3-app] Clean termination with exit code 0` | Application teardown completed via public `SDL_Quit()`. |
| **E16** | Desktop Exit 0 | `userspace/desktop` | `[desktop] child Process-cap exit status=0` | Compositor observing clean exit status 0 from child process. |
| **E17** | UEFI Shutdown | `kernel/efi` | `halting via UEFI ResetSystem(shutdown)` | Kernel clean powerdown invoked via serial shutdown command. |

### 1.2 Strict Chronological Sequence Ordering

All test harnesses (`tools/test_sdl3_guest.py` and `tools/test_upstream_sdl3_guest.py`) enforce that events must appear in strict chronological order:
$$\text{pos}(E_1) < \text{pos}(E_2) < \dots < \text{pos}(E_{17})$$
If any marker is absent, or if an event occurs out of order (e.g. frame milestone 25 appearing after frame milestone 60, or mouse input handled before window creation), the test fails closed with exit code 1.

## 2. Automated Source / Contract Consistency Enforcement

To prevent future divergence between application sources and qualification harnesses, `tools/test_sdl3_guest_mock.py` implements an automated source-inspection test: `TestSourceContractConsistency.test_source_contract_consistency()`.

This test reads `experimental/sdl3-app/src/main.c` directly as text and verifies:
1. Video initialization string exists verbatim in `main.c`.
2. Window creation string exists verbatim in `main.c`.
3. Surface acquisition string exists verbatim in `main.c`.
4. Frame loop entry string exists verbatim in `main.c`.
5. Frame milestone format string `[sdl3-app] Frame milestone reached: frame=%d; damage published (box at %d,%d, color=%d)` exists verbatim in `main.c`.
6. Specific milestone frames `(0, 25, 60, 90, 119)` are explicitly checked in the loop condition in `main.c`.
7. Mouse button down event with coordinates and state transition exists verbatim in `main.c`.
8. Spacebar key press event with state transition exists verbatim in `main.c`.
9. Clean termination string `[sdl3-app] Clean termination with exit code 0` exists verbatim in `main.c`.

If any developer alters the format strings in `main.c` without updating the harness, or vice versa, the mock test suite fails immediately before any guest execution is attempted.

## 3. Graphics Runtime Capabilities and Syscall Architecture Review

### 3.1 Broker Capability Table (V2 Desktop Contract)

When the ArenaOS Desktop broker launches a graphical child process, it constructs a capability table conforming to the V2 contract:

| Slot Index | Capability Role | Type | Granted Rights | Purpose & Syscall Authority |
|---|---|---|---|---|
| **Slot 0** | Null Slot | Null | None | Invalid slot / null handle. |
| **Slot 1** | Service Endpoint | Endpoint | `CALL` | IPC channel to Desktop compositor broker. |
| **Slot 2** | Surface Memory | SharedMemory | `READ \| WRITE` (0x03) | 320x240 ARGB8888 window pixel buffer. |
| **Slot 3** | Notification Cap | Notification | `READ \| WRITE` (0x03) | Hardware timer delivery and sleep waiting. |

### 3.2 Syscall Verification

Syscall numbers and signatures match `userspace/abi.rs` exactly:

1. **`SYS_TIMER_ARM` (Syscall 27):**
   - Signature: `arenaos_syscall3(SYS_TIMER_ARM, notif_slot, badge, relative_delay_us)`
   - Requirements: `notif_slot` must hold a Notification capability with `RIGHTS_WRITE` authority.
   - Return: Positive 32-bit `timer_id` on success; negative error code on failure.
   - Validation: Slot 3 has `RIGHTS_WRITE`, satisfying this requirement.

2. **`SYS_TIMER_CANCEL` (Syscall 28):**
   - Signature: `arenaos_syscall1(SYS_TIMER_CANCEL, (uint64_t)timer_id)`
   - Requirements: Accepts the active 32-bit `timer_id` returned by `SYS_TIMER_ARM`.
   - Architectural Constraint: Does **NOT** accept capability slot indices. Passing a capability slot (e.g., Slot 3) is invalid.
   - Return: `0` on success; `STATUS_BAD_ARG` if `timer_id` is unknown or already fired.

3. **`SYS_WAIT` (Syscall 11):**
   - Signature: `arenaos_syscall1(SYS_WAIT, notif_slot)`
   - Requirements: `notif_slot` must hold a Notification capability with `RIGHTS_READ` authority.
   - Return: Bitmask badge delivered by kernel interrupt handler.
   - Blocking Semantics: The kernel transitions the calling thread from `RUNNABLE` to `BLOCKED`, yielding the CPU. **No busy spinning occurs.**

### 3.3 Safe Sleep Implementation (`adsk_sleep_ms`)

The client sleep adapter in `experimental/sdl3/src/platform/arenaos/arenaos_client.c` implements direct timer arming and blocking waiting without busy-wait loops:

```c
void adsk_sleep_ms(uint32_t ms) {
    if (ms == 0) return;
    uint64_t us = (uint64_t)ms * 1000ULL;
    int64_t timer_id = arenaos_syscall3(SYS_TIMER_ARM, CLOCK_SLOT, 1, us);
    if (timer_id >= 0) {
        int64_t w = arenaos_syscall1(SYS_WAIT, CLOCK_SLOT);
        if (w < 0) {
            /* If wait was aborted before badge delivery, disarm the timer */
            arenaos_syscall1(SYS_TIMER_CANCEL, (uint64_t)timer_id);
        }
    }
}
```

### 3.4 Cleanup on Partial Initialization Failure

The graphics runtime enforces strict resource cleanup during partial failure:
- **`adsk_connect` Failure Handling:**
  If `SYS_SHARED_INFO` or `SYS_SHARED_MAP` fails, `s_surface_va` remains `NULL`.
  If IPC exchange (`Frame::Create`) fails or returns an invalid handle, `SYS_SHARED_UNMAP` is immediately invoked on `s_surface_va`, resetting it to `NULL` before returning `false`.
- **`ARENAOS_CreateWindowFramebuffer` Failure Handling:**
  If `adsk_connect` fails, no surface is stored in `SDL_WindowData`.
- **`ARENAOS_DestroyWindow` / `adsk_disconnect`:**
  Sends `DestroyWindow` (op 11) to compositor broker, then unmaps the shared memory region via `SYS_SHARED_UNMAP`.

## 4. Upstream SDL 3.2.0 24-Step Lifecycle Contract

For genuine upstream SDL 3.2.0 targets (`Target C2` and `Target Standalone`), the test harness enforces a 24-step lifecycle:

```
[Host Preflight]
Step 1:  Host Environment & QEMU Binary Preflight Verification
Step 2:  Guest Bootloader & Firmware Artifact Extraction & SHA-256 Verification
Step 3:  Target Binary, Library, & APB1 Package Hash Integrity
Step 4:  Deterministic ELF Loader Budget Audit (Size <= 256 KiB, Pages <= 128)
Step 5:  Whole-Executable ISA Disassembly Audit (Scan all PT_LOAD segments)
Step 6:  Kernel CPU-State Capability Gate Inspection (CR4.OSFXSR & FXSAVE/XSAVE)

[Disk & VM Setup]
Step 7:  AFS2 Filesystem Scratch Image Volume Allocation & Partition Verification
Step 8:  AFS2 Desktop Bundle Seeding (Unlink stale, seed target APB1 bundle)
Step 9:  Virtual Console, Network Socket Fixtures, & QEMU Process Launch
Step 10: QMP Monitor Socket Connection & Capability Negotiation

[Guest Boot & Compositor Handshake]
Step 11: EDK2 UEFI Firmware Boot & Memory Map Initialization
Step 12: ArenaOS Kernel Boot, Page Tables Setup, & Memory Manager Initialization
Step 13: Capability Space Setup, Bootstrap Slot Assignments, & IPC Endpoints
Step 14: User-Space Init Handover & System Daemon Spawning
Step 15: Compositor & Desktop Broker Server Initialization
Step 16: Desktop Surface Enumeration & Desktop Item Discovery (/Users/user/Desktop)

[Application Activation & Installation]
Step 17: Pointer Double-Click Activation of Target APB1 Desktop Item
Step 18: Desktop APB1 Signature Verification & Protected Package Installation
Step 19: Post-Installation AFS2 Filesystem Tree Audit (/System/Applications/.../bin/...)

[Runtime Execution & Visual Verification]
Step 20: Application Launch via Desktop All Applications Menu Search
Step 21: Upstream SDL3 Video Subsystem Initialization & Display Driver Handshake
Step 22: Upstream SDL3 Window Creation & Window Surface Acquisition
Step 23: Interactive Multi-Frame Rendering & Event Processing (Frames 0, 25, 59, mouse/key)
Step 24: Clean Application Termination (Code 0), Compositor Cleanup, & Graceful UEFI Shutdown
```

All 24 steps are executed and verified under `tools/test_upstream_sdl3_guest.py`, ensuring consistent, reproducible verification across the ArenaOS graphics stack.
