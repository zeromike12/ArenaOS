## 1. Executive Context & Architectural Objectives

Milestone G2.3.1 addresses the findings from the comprehensive architectural review of Milestones G2.2.2 and G2.3. The review identified four key findings requiring technical remediation and documentation correction:

1. **Finding A — Baseline Log Contract Divergence:**  
   The baseline demo application (`experimental/sdl3-app/src/main.c`) emitted:
   `[sdl3-app] frame rendered; damage published; frame=%d (box at %d,%d, color=%d)` and
   `[sdl3-app] Event: Mouse button down at (%d, %d) -> state transition color=%d`.
   Conversely, the test harness (`tools/test_sdl3_guest.py`) asserted against:
   `[sdl3-app] Frame milestone reached: frame=%d` and `[sdl3-app] Event: Mouse button pressed`.
   This divergence meant mock suites and real execution were decoupled from the actual application source.

2. **Finding B — Upstream Guest Harness Lacked Real 24-Step Lifecycle:**  
   `tools/test_upstream_sdl3_guest.py` implemented only an early refusal exit without a runnable guest execution pipeline. While CPU-state gating is necessary, the harness required a complete 24-step lifecycle that conditionally executes when an FP/SIMD-capable kernel is provided and fails closed with code 2 only when the kernel lacks CPU-state saving or when QEMU is unavailable.

3. **Finding C — Overstated Qualification Status:**  
   Milestone G2.3 documentation used the status `APPROVED & QUALIFIED` despite real QEMU guest testing being unavailable in the host environment (`GUEST-NOT-RUN`) and upstream guest execution being architecturally blocked on kernel CPU-state context preservation (`BLOCKED`). The authoritative status must be `BUILD-READY / NATIVE GUEST QUALIFICATION PENDING`.

4. **Finding D — Shared C Runtime Provenance & `_exit` Symbol Resolution:**  
   The copy of Arena 2's C runtime (`experiments/c-runtime`) required machine-readable proof of provenance against Arena 2 revision `84392b8f32a0b1ce26364926185723c7bbf7a3f3`. Furthermore, the absence of `_exit` in the linked binary symbol table required rigorous explanation (GNU ld dead-code elimination via `--gc-sections`).

## 2. Work Breakdown Structure (WBS)

### Task A: Baseline Guest Harness Log Contract Reconciliation
- **Objective:** Establish one authoritative observable log contract between `experimental/sdl3-app/src/main.c` and `tools/test_sdl3_guest.py`.
- **Implementation:**
  - Update `experimental/sdl3-app/src/main.c` to emit the unified contract format:
    `[sdl3-app] Frame milestone reached: frame=%d; damage published (box at %d,%d, color=%d)`.
  - Update `tools/test_sdl3_guest.py` to match exact frame milestones (0, 25, 60, 90, 119), mouse button-down events, Spacebar events, state transitions (`color=X`), clean process exit 0, and compositor child exit status 0.
  - Implement `verify_baseline_contract_sequence()` in `tools/test_sdl3_guest.py` to verify chronological ordering of all emitted markers.
  - Add `test_source_contract_consistency()` in `tools/test_sdl3_guest_mock.py` that reads `main.c` directly to prevent future drift.
  - Expand negative controls in `tools/test_sdl3_guest_mock.py` (missing frames, wrong order, unhandled input, corrupted screenshots, timeout, nonzero exit, UEFI shutdown failure).

### Task B: Dedicated Upstream SDL3 24-Step Guest Harness
- **Objective:** Replace refusal-only workflow with a conditionally executable 24-step guest lifecycle in `tools/test_upstream_sdl3_guest.py`.
- **Implementation:**
  - Support modes `audit`, `guest`, and `auto`; support targets `c2`, `standalone`, and `all`.
  - Implement Step 1 through Step 24 in `run_upstream_guest_lifecycle()` covering preflight, artifact extraction, budget audit, ISA audit, CPU-state gate, disk preparation, bundle seeding, QEMU spawn, QMP handshake, boot, compositor init, desktop double-click, APB1 install, AFS2 verification, search bar launch, window surface init, multi-frame rendering, and UEFI shutdown.
  - Implement `inspect_kernel_simd_capability()` to inspect exact kernel artifact SHA-256 and content rather than assuming Phase 15.
  - If kernel lacks FP/SIMD saving, report BLOCKED (exit code 2); if QEMU missing, report NOT RUN (exit code 2); if kernel is SIMD-capable, execute full 24 steps to completion (exit code 0).
  - Update `tools/test_upstream_sdl3_guest_mock.py` to 15 tests covering all modes, targets, lifecycle execution, and negative assertions.

### Task C: Shared C Runtime Integration & Provenance Verification
- **Objective:** Machine-readable comparison of `experiments/c-runtime` against Arena 2 revision `84392b8f32a0b1ce26364926185723c7bbf7a3f3`.
- **Implementation:**
  - Execute `git diff-tree -r 84392b8f32a0b1ce26364926185723c7bbf7a3f3 HEAD -- experiments/c-runtime`.
  - Verify identical git tree object hash: `0475670175bf8dcfd2883bce3a9a56a7eca06a14`.
  - Explain why `_exit` is absent in final linked binary: GNU ld `--gc-sections` discards unreferenced `.text._exit` from `arenaos_c2_glue.o` because standard C runtime paths route through `crt0.o` -> `arena_libc_exit()`.
  - Author `docs/graphics/G2.3.1-C2-PROVENANCE.md`.

### Task D: Graphics Runtime Capability and Syscall Contract Review
- **Objective:** Review capability rights on Slot 3, syscall numbers, blocking wait behavior, and partial initialization cleanup.
- **Implementation:**
  - Verify Desktop launch broker grants `RIGHTS_READ | RIGHTS_WRITE` (0x03) on Slot 3 (`V2_CLOCK_SLOT = 3`).
  - Verify syscall numbers: `SYS_TIMER_ARM = 27`, `SYS_TIMER_CANCEL = 28`, `SYS_WAIT = 11`.
  - Verify `adsk_sleep_ms` uses direct timer arm and wait without busy spinning, cancelling active timers on early interruption.
  - Verify cleanup routines in `adsk_connect`, `adsk_disconnect`, and `ARENAOS_CreateWindowFramebuffer` properly unmap shared memory on failure.
  - Author `docs/graphics/G2.3.1-TEST-CONTRACT.md`.

### Task E: Qualification Documentation Correction
