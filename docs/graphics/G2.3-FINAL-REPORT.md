## 3. Linker Conflict Resolution & Symbol Ownership

### 3.1 Symbol Collision Resolution
When combining genuine upstream SDL 3.2.0 with the Arena 2 shared C runtime (`libarena_c.a`), the primary conflict arises from internal libc fallbacks inside `SDL_memcpy.c`, `SDL_memmove.c`, and `SDL_memset.c`.
In upstream SDL3 source:
```c
#ifndef HAVE_LIBC
void *memcpy(void *dst, const void *src, size_t len) { return SDL_memcpy(dst, src, len); }
#endif
```
By defining `-DHAVE_LIBC=1` across the upstream build, these fallback declarations are suppressed. The linker resolves `memcpy`, `memmove`, and `memset` exclusively from `libarena_c.a(libc_names.o)`.

### 3.2 POSIX Process Termination and Dead-Code Elimination
Upstream SDL3 invokes `_exit(exitcode)` on internal panic or termination. Standard C runtimes provide `_Exit()` (C11) and `exit()`, but not POSIX `_exit()`. The glue module `arenaos_c2_glue.c` provides:
```c
#include <stdlib.h>
void _exit(int status) {
    _Exit(status);
}
```
This safely routes all termination through `arena_libc_exit()` in `crt0.o`. In the final linked binary, because `SDL_ExitProcess` is unreferenced in normal execution paths and `crt0.o` directly calls `arena_libc_exit(rc)`, the GNU ld linker `--gc-sections` pass cleanly eliminates `.text._exit` as dead code. This explains why `_exit` is absent from the final stripped and unstripped ELF symbol table while still satisfying any potential unreferenced dependencies during link time.

### 3.3 Linker Symbol Ownership Verification
Inspection of the final binary symbol table (`nm` and `sdl3_upstream_c2.map`):
- `main`, `draw_box`: Owned by `demo_main.o`.
- `SDL_Init`, `SDL_CreateWindow`, `SDL_GetWindowSurface`, `SDL_UpdateWindowSurface`: Owned by `libSDL3_upstream_c2.a`.
- `adsk_connect`, `adsk_create_window`, `adsk_map_surface`, `adsk_present`: Owned by `arenaos_client.o`.
- `_start`, `arena_crt_start`, `arena_startup_gate`: Owned by `crt0.o`.
- `malloc`, `free`, `realloc`, `calloc`: Owned exclusively by `libarena_c.a(alloc.o)`.
- `memcpy`, `memmove`, `memset`: Owned exclusively by `libarena_c.a(libc_names.o)`.
- `_Exit`, `exit`: Owned exclusively by `libarena_c.a(libc_names.o)`.
- `_exit`: Owned by `arenaos_c2_glue.o`.

## 4. Architectural CPU State Gate & Blocker B1 / B-FP-2 Handoff

### 4.1 Strict Guest Execution Gate
Whole-executable disassembly ISA scanning of `sdl3_upstream_c2` confirms 2,036 `%xmm` SIMD instructions emitted by GCC for System V AMD64 ABI compliance:
- Return values of `float` parameters in `%xmm0`.
- Floating-point geometry clipping and color space calculations.
- Software blitters (`SDL_Blit_Slow_Float`, 486 hits).

Under current ArenaOS kernel releases (Phase 13 / Phase 14):
1. `CR4.OSFXSR` and `CR4.OSXSAVE` are not enabled for user-mode processes. Executing an SSE instruction triggers CPU vector `0x06` (`#UD`, Invalid Opcode).
2. Per-thread FPU/SIMD register contexts (`%xmm0`–`%xmm15`, `MXCSR`) are not preserved across task preemptions.

### 4.2 Handoff to Core-OS Milestone (Luna Phase 15)
Branch `arena/phase15-fpu-simd` (commit `0182b5a1910efdb9d77e489e2467d16a69ef2db4` / `33cd7d7dfec759a2d983156b27306a6f8e69d174`) introduces the proposed kernel-level FPU/SIMD state management. Once merged into mainline:
1. Kernel enables `CR4.OSFXSR`.
2. Kernel executes `FXSAVE64` / `FXRSTOR64` (or `XSAVE` / `XRSTOR`) on thread context switches.
3. Upstream SDL3 binaries (`sdl3_upstream_c2` and `sdl3_upstream_demo`) can immediately transition from `BLOCKED` to `PASS` under guest execution without recompilation.
