## 2. Separation of Failures & Architectural Boundaries

To avoid regressions or misleading claims, failures and blockers are strictly classified:

| Failure / Blocker | Category | Responsible Owner | Mitigation / Action in G2.2 |
|---|---|---|---|
| **Discrepancy in G2.1 memory reports** (98 pages vs 100 pages, 238,840 B vs 246,912 B) | Measurement discrepancy | Arena 1 | Reconcile reports against deterministic build; document previous measurement of `/tmp/upstream_sdl3_demo`. |
| **Allocator 16-byte alignment defect** (24-byte header offset) | Implementation defect | Arena 1 | Refactor `arenaos_memory.c` with 32-byte header (16-byte aligned payload), ownership magic, and unit tests. |
| **Weak allocator ownership & double-free checks** | Safety defect | Arena 1 | Add magic tags, bounds verification, double-free detection, and safe realloc. |
| **Partial startup validation** in `arenaos_entry.c` | Verification gap | Arena 1 / Arena 2 | Implement comprehensive ARST v2 canonical validation and full live capability inventory check via `SYS_CAP_DESCRIBE`. |
| **Timer cancel contract misuse** (`CLOCK_SLOT` instead of `timer_id`) | Protocol defect | Arena 1 | Audit timer syscall contract; pass correct `timer_id`; eliminate redundant cancel on already-fired timers. |
| **ADSK-v1 damage rects truncation** (clamping `count > 5` to 5) | Protocol defect | Arena 1 | Fall back to full-window damage when dirty rect count exceeds 5; clip rect bounds safely. |
| **ADSK-v1 key release absence** | Protocol boundary | Desktop Compositor | Document limitation: ADSK-v1 delivers atomic `Event::Key(code)` without up/down flags; single key-down/up pair is the sound SDL translation. |
| **Blocker B1 / B-FP-2: Kernel `#UD` on SSE** | OS / CPU Architecture | Luna (Phase 14) / Kernel | Document exact dependencies in `G2.2-CPU-DEPENDENCIES.md`; classify upstream guest execution as BLOCKED. |
| **Blocker B-GFX-1: No service identity in ARST v2** | Architecture / ABI | System Architecture | Prepare handoff in `G2.2-C2-INTEGRATION.md` for role or protocol identification. |

## 3. Work Breakdown & Execution Roadmap

### G2.2.1: Memory & ELF Report Reconciliation
1. Implement deterministic ELF audit tool (`tools/audit_elf.py`) verifying exact kernel rules (`kernel/kernel/src/image_registry.rs`).
2. Correct `docs/graphics/G2.1-MEMORY-REPORT.md` to document the exact provenance of the 98-page / 238,840-byte build versus the earlier intermediate 100-page / 246,912-byte binary.
3. Ensure all reports and test receipts reference the same artifact identities.

### G2.2.2: Eliminating Unsafe Allocator Scaffolding
1. Refactor `arenaos_memory.c`:
   - Change `BlockHeader` to 32 bytes (16-byte aligned) containing magic tag `0x4152454E414D454DLL` (`ARENAMEM`), block size, allocation state, and free list pointers.
   - Enforce 16-byte alignment for all returned pointers: `(uintptr_t)ptr % 16 == 0`.
   - Validate pointer ownership before freeing or reallocating: check heap bounds, pointer alignment, header magic, and live allocation state.
   - Implement safe `calloc` with integer overflow protection.
   - Implement safe `realloc`: refuse invalid pointers, preserve existing block on allocation failure.
2. Author host test suite (`experimental/upstream-sdl3/tests/test_allocator.c`) covering:
   - 16-byte alignment
   - Realloc expansion and reduction
   - Invalid pointer refusal (foreign pointers, interior pointers, unaligned pointers)
   - Double-free detection
   - Heap exhaustion behavior

### G2.2.3: Replace Partial Startup Validation
1. Port canonical ARST v2 validation and live inventory verification into `arenaos_entry.c`:
   - Check slot 0 type (`SharedRegion`), rights (`READ | DESTROY`), and page count (1).
   - Snapshot 4096-byte ARST v2 page into `.bss`, unmap, and destroy slot 0.
   - Parse ARST v2 canonical header, flags, limits, and string tables.
   - Run exact live capability audit across all 128 slots using `SYS_CAP_DESCRIBE`:
     - Listed slots 1..`capc` must be occupied with expected kind and rights.
     - Unlisted slots `capc + 1 .. 128` must be empty.
   - Validate required graphics capabilities: BadgedEndpoint (slot 1), SharedRegion (slot 2), Notification (slot 3).
2. Author standalone negative test harness verifying that malformed ARST records, incorrect rights, or unexpected capability grants fail closed.

### G2.2.4: Correct Timer and Event Handling
1. Audit timer syscall contract in `kernel/kernel/src/arch/x86_64/syscall.rs`:
   - `SYS_TIMER_ARM(notif_slot, badge, delay_us)` returns `timer_id >= 0`.
   - `SYS_WAIT(notif_slot)` blocks until badge delivery.
   - If timer fires, it expires; do not call `SYS_TIMER_CANCEL`.
   - If wait is cancelled or aborted, call `SYS_TIMER_CANCEL(timer_id)` with `timer_id`, NOT the capability slot.
2. Fix `arenaos_client.c`:
   - Correct `adsk_sleep_ms` and `retry_after_busy` to track `timer_id`.
   - Correct `adsk_damage_rects`: when `count > 5` or rects are invalid, fall back to `adsk_damage_full()`.
   - Correct `ARENAOS_UpdateWindowFramebuffer` in `SDL_arenaosframebuffer.c`: handle clipping and fall back to full damage rather than truncating to 5 or emitting 1x1 damaged regions.
3. Document ADSK-v1 single key event semantics and window destruction cleanup.

### G2.2.5: Strengthen Floating-Point / SIMD Auditing
1. Build disassembly-based instruction scanner (`tools/isa_audit.py`) with self-test:
   - Inspects only FUNC symbol ranges.
   - Categorizes instructions (SSE/SSE2 vs x87 vs AVX vs general).
   - Identifies responsible functions and object files.
2. Produce `docs/graphics/G2.2-CPU-DEPENDENCIES.md` for Luna Phase 14 handoff.

### G2.2.6: Harden Upstream SDL3 Backend
1. Clean up resource allocation in `ARENAOS_CreateDevice`, `ARENAOS_VideoInit`, `ARENAOS_CreateSDLWindow`.
2. Ensure double destruction or partial teardown does not leak or dereference invalid handles.

### G2.2.7: Integration with Arena 2 C2 Runtime
1. Evaluate C2 static runtime library (`experiments/c-runtime/build/guest-gcc/lib/libarena_c.a`).
2. Document architectural integration and blocker B-GFX-1 in `docs/graphics/G2.2-C2-INTEGRATION.md`.

### G2.2.8: Separate Baseline and Upstream Qualification
1. Restructure `tools/test_sdl3_guest.py` into distinct targets:
   - Target A: Hardened Baseline (QEMU guest execution, input testing, screenshot verification, clean exit).
   - Target B: Genuine Upstream SDL3 (build provenance, ELF audit, ISA scan; explicit report of execution blocked on CPU state).
2. Prohibit silent fallbacks from guest tests to static audits.

### G2.2.9: Final Verification, Evidence & Closure
1. Rebuild and verify all targets.
2. Produce `docs/graphics/G2.2-FINAL-REPORT.md`.
3. Commit cleanly on `arena/13f9221b-arenaos` and report final SHA and handoff summary.
