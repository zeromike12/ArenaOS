## 1. Purpose & Scope

This document defines the interface contract between the ArenaOS Graphics subsystem (specifically the genuine upstream SDL 3.2.0 port) and the native C runtime owned by Arena 2. It responds directly to the findings and requests in Arena 2's `C1-SDL3-HANDOFF.md` and aligns with ADR-0110 (*Native C Runtime Profile Proposal*).

Graphics Milestone G2.1 establishes that genuine upstream SDL3 can be compiled into a static freestanding archive (`libSDL3_upstream.a`) and linked against native user binaries without POSIX libc dependencies, provided that specific runtime guarantees and standard symbols are maintained.

## 2. Startup & Capability Invariant Verification

The startup gate must enforce fail-closed security. Arena 1 adopts the ARST v2 protocol specified in `userspace/arena-platform/src/startup.rs` and implemented in C1 `startup.c`:

1. **Slot 0 ARST View**:
   - Must be verified via `SYS_CAP_DESCRIBE` as `SharedRegion` (kind 7) with exact rights `READ | DESTROY`.
   - Must be mapped read-only, copied to private `.bss`, unmapped, and destroyed via `SYS_CAP_DESTROY` before application initialization.
   - Parsing must validate ARST v2 magic (`0x54535241`), header bytes, string offsets, and canonical role uniqueness.
2. **Live Capability Table Verification**:
   - Every granted capability slot must be confirmed via `SYS_CAP_DESCRIBE` to verify expected kinds and rights:
     - `Desktop Service BadgedEndpoint`: kind 12, `WRITE` rights.
     - `Window Surface SharedRegion`: kind 7, `READ | WRITE` rights.
     - `Clock Device`: kind 3.
   - Any discrepancy or unexpected capability slot must terminate immediately with exit code 1.

## 3. Dynamic Memory Allocation Contract

Upstream SDL 3.2.0 contains an internal dlmalloc implementation (`src/stdlib/SDL_malloc.c`) that spans over 6,300 lines and requires POSIX kernel primitives (`mmap`, `munmap`, `mremap`, `sbrk`, `sched_yield`, `sysconf`, `__errno_location`).

### 3.1 Upstream `HAVE_MALLOC` Bypass
By configuring `#define HAVE_MALLOC 1` in `SDL_build_config_arenaos.h`, upstream SDL3 bypasses dlmalloc entirely and delegates memory management to the platform:
```c
#ifdef HAVE_MALLOC
static void* SDLCALL real_malloc(size_t s) { return malloc(s); }
static void* SDLCALL real_calloc(size_t n, size_t s) { return calloc(n, s); }
static void* SDLCALL real_realloc(void *p, size_t s) { return realloc(p, s); }
static void  SDLCALL real_free(void *p) { free(p); }
#endif
```

### 3.2 Arena 2 C Runtime Mapping
Arena 1 requests that Arena 2 export the standard allocator names as aliases to the buddy allocator (`alloc.c`):
```c
void *malloc(size_t size) { return arena_malloc(size); }
void *calloc(size_t nmemb, size_t size) { return arena_calloc(nmemb, size); }
void *realloc(void *ptr, size_t size) { return arena_realloc(ptr, size); }
void free(void *ptr) { arena_free(ptr); }
```
**Budget Constraint**: The allocator must operate within the process VM quota (8 regions, 4,096 pages per region). In G2.1, Arena 1 configured a temporary heap of 128 KiB (32 pages), which easily satisfies SDL3's window and surface management needs while keeping total load pages well under `MAX_LOAD_PAGES = 128`.

## 4. Libc Symbol Matrix & Upstream Self-Sufficiency

Arena 2's `C1-SDL3-HANDOFF.md` expressed concern that SDL3 requires a large POSIX libc surface. Our audit of upstream SDL 3.2.0 demonstrates that upstream SDL3 is largely self-contained when appropriately configured:

| Function Family | Needed by SDL3? | Provider in G2.1 | Requested from Arena 2 (C2) |
|---|---|---|---|
| `memcpy`, `memmove`, `memset`, `memcmp` | **Yes** | Provided by C1 (`string.c`) and SDL3 (`SDL_mem*.c`). | Standard aliases exported globally. |
| `strlen`, `strcmp`, `strncmp` | **Yes** | Provided by C1 (`string.c`) and SDL3 (`SDL_str*.c`). | Standard aliases exported globally. |
| `malloc`, `free`, `calloc`, `realloc` | **Yes** | Temporary scaffolding in G2.1; aliases to C1 `alloc.c`. | Standard names exported from `alloc.c`. |
| `_exit`, `exit` | **Yes** | Syscall wrapper `SYS_THREAD_EXIT`. | Standard `_exit` in `crt0.c`. |
| `snprintf`, `vsnprintf` | **Yes** | C1 `stdio.c` provides integer formatting. | Retain integer-only `arena_snprintf`. |
| `qsort` | **Yes** | Upstream `SDL_qsort.c` handles internally. | None (self-contained). |
| `strtol`, `strtoll`, `strtoul` | **Yes** | Upstream `SDL_strtol.c` handles internally. | None (self-contained). |
| `pow`, `floor`, `fabs`, `sqrt`, `sin`, `cos` | **Yes** | Upstream `src/libm/` (uClibc) handles internally. | None (self-contained). |
| POSIX file I/O (`fopen`, `fread`, etc.) | **No** | Disabled via `SDL_FILESYSTEM_DUMMY 1`. | None. |
| Dynamic loading (`dlopen`, `dlsym`) | **No** | Disabled via `SDL_LOADSO_DUMMY 1`. | None. |
| POSIX sockets / network | **No** | Not referenced. | None. |

**Verdict**: SDL3 does **not** require a general POSIX libc or dynamic loader. Only 4 allocator functions (`malloc`, `free`, `calloc`, `realloc`) and `_exit` are required from the C runtime.

## 5. Monotonic Timing Contract

Upstream SDL3 requires monotonic time for `SDL_GetTicks()` and `SDL_Delay()`:
- `SDL_GetPerformanceCounter()`: Returns monotonically increasing microseconds from `SYS_CLOCK_NOW`.
- `SDL_GetPerformanceFrequency()`: Returns constant `1,000,000ULL` (microsecond resolution).
- `SDL_SYS_DelayNS(Uint64 ns)`: Invokes non-blocking or coarse timer wait via `SYS_TIMER_ARM` and `SYS_WAIT`.

Arena 1 implemented this in `SDL_systimer.c`. Arena 2's `arena_clock_us()` aligns with this requirement.

## 6. Shared Blocker: Floating-Point & SIMD Calling Convention

Arena 1 fully validates Arena 2's findings in `C1-FPSIMD-BOUNDARY.md`:
- Upstream SDL3 includes functions returning scalar `float` (e.g. `SDL_GetWindowDisplayScale`).
- GCC on x86_64 enforces System V AMD64 ABI conventions, which require passing and returning floats in `%xmm0`. Compiling with `-mno-sse` triggers `error: SSE register return with SSE disabled`.
- When compiled with SSE enabled, the resulting executable contains `%xmm` instructions (2,029 instructions in our genuine build).
- Executing these instructions in ring 3 triggers `#UD` (vector 0x06) because the kernel does not enable `CR4.OSFXSR`, and would corrupt state across context switches because `switch_context` saves no FP state.

**Handoff Action for Luna**:
Both Arena 1 and Arena 2 record this as an external core-OS dependency on Luna (scheduled for Phase 14 review).
