## 1. Executive Summary & Remediation Mandate

Milestone G2 delivered a working, signed, native ring-3 desktop application (`SDL3App.apb1`) running on ArenaOS, demonstrating window creation, software rasterization, damaged-region presentation over the ADSK-v1 protocol, keyboard/mouse event handling, and clean process teardown. However, architectural review identified that the G2 baseline relied on an experimental API-compatible prototype rather than genuine upstream SDL 3.2.0 internals, and required explicit remediation:

1. **Clear Attribution & Terminology**: The G2 demonstration must be clearly documented as an experimental baseline, distinguishing it from full upstream SDL3.
2. **Authentic Upstream Source Requirement**: Upstream SDL 3.2.0 must be integrated directly via upstream's designated `SDL_VIDEO_DRIVER_PRIVATE` and `PRIVATE_bootstrap` interfaces, rather than using facade or mock libraries.
3. **Fail-Closed Validation**: Startup data and capability grants must be strictly validated against live kernel metadata using `SYS_CAP_DESCRIBE` rather than assuming valid slots.
4. **Honest Architectural Porting**: Semantics must not be weakened or mocked merely to produce a passing demonstration. If kernel CPU state management (FPU/SSE), executable image quotas (`MAX_LOAD_PAGES`), or C runtime facilities block full upstream execution, the integration must stop at a verifiable checkpoint and report exact blockers.

## 3. Upstream SDL 3.2.0 Integration Architecture

### 3.1 Upstream Driver Bootstrap (`PRIVATE_bootstrap`)

Upstream SDL 3.2.0 provides an official mechanism for out-of-tree and embedded platform drivers via `SDL_VIDEO_DRIVER_PRIVATE`:
```c
// In src/video/SDL_video.c:
static VideoBootStrap *bootstrap[] = {
#ifdef SDL_VIDEO_DRIVER_PRIVATE
    &PRIVATE_bootstrap,
#endif
...
};
```
When `SDL_VIDEO_DRIVER_PRIVATE` is defined, upstream's `SDL_Init(SDL_INIT_VIDEO)` evaluates `PRIVATE_bootstrap` as the primary video driver candidate. The bootstrap structure defines driver identity and factory instantiation:
```c
typedef struct VideoBootStrap {
    const char *name;
    const char *desc;
    SDL_VideoDevice *(*create)(void);
    bool (*ShowMessageBox)(const SDL_MessageBoxData *messageboxdata, int *buttonID);
} VideoBootStrap;
```
For ArenaOS, `PRIVATE_bootstrap` is implemented in `experimental/upstream-sdl3/src/video/arenaos/SDL_arenaosvideo.c` with name `"arenaos"` and description `"ArenaOS native video driver"`.

### 3.2 `SDL_VideoDevice` Vtable Implementation

The factory function `ARENAOS_CreateDevice()` allocates and configures the `SDL_VideoDevice` vtable:
- **Lifecycle**: `VideoInit` registers the default display mode (retrieved from Desktop via ADSK-v1 greeting) and calls `SDL_AddBasicVideoDisplay`. `VideoQuit` tears down allocated device state.
- **Window Management**: `CreateSDLWindow` reserves window structures and maps `SDL_WindowData`. `DestroyWindow` frees native window allocations. `ShowWindow` and `HideWindow` issue visibility state transitions.
- **Software Framebuffer**:
  - `CreateWindowFramebuffer`: Attaches the window's backing buffer to the `SharedRegion` granted by Desktop, setting `*format = SDL_PIXELFORMAT_ARGB8888`, `*pitch = width * 4`, and `*pixels = (void *)shm_addr`.
  - `UpdateWindowFramebuffer`: Translates the dirty rectangle list into `ADSK_OP_DAMAGE` IPC messages sent over the window channel via `SYS_CHANNEL_SEND`.
  - `DestroyWindowFramebuffer`: Cleans up the surface properties associated with the framebuffer.
- **Event Pumping**:
  - `PumpEvents`: Executes non-blocking `SYS_CHANNEL_RECV` on the window channel.
  - Injects keyboard events into SDL core via `SDL_SendKeyboardKey`.
  - Injects mouse motion into SDL core via `SDL_SendMouseMotion`.
  - Injects mouse clicks into SDL core via `SDL_SendMouseButton`.
  - Injects window lifecycle events (resize, close requested) via `SDL_SendWindowEvent`.

### 3.3 Subsystem Trimming & Build Configuration

To compile genuine upstream SDL 3.2.0 in a freestanding environment without POSIX dependencies, `include/build_config/SDL_build_config_arenaos.h` configures the build:
- Disables unused subsystems: `SDL_AUDIO_DISABLED`, `SDL_GPU_DISABLED`, `SDL_RENDER_DISABLED`, `SDL_JOYSTICK_DISABLED`, `SDL_HAPTIC_DISABLED`, `SDL_HIDAPI_DISABLED`, `SDL_CAMERA_DISABLED`, `SDL_POWER_DISABLED`, `SDL_SENSOR_DISABLED`, `SDL_DIALOG_DISABLED`.
- Enforces dummy interfaces for unsupported OS facilities: `SDL_FILESYSTEM_DUMMY`, `SDL_FSOPS_DUMMY`, `SDL_LOADSO_DUMMY`, `SDL_PROCESS_DUMMY`, `SDL_ASYNCIO_DISABLED`.
- Sets `#undef SDL_PLATFORM_LINUX` and `#define SDL_PLATFORM_ARENAOS 1` to prevent upstream code from invoking Linux-specific files (`/sys/...`) or flatpak/snap queries (`access`).
- Defines `HAVE_MALLOC 1` to bypass upstream's 6,300-line dlmalloc implementation (which requires `mmap`, `munmap`, `sbrk`, and `sysconf`), redirecting memory operations directly to the C runtime allocator.

## 4. Architectural Blockers & Dependencies

Investigation of genuine upstream SDL 3.2.0 revealed two major blockers that prevent full ring-3 execution of the complete upstream library without kernel changes:

### 4.1 Blocker B1: Floating-Point & SIMD Calling Convention
- **Root Cause**: Upstream SDL3 includes functions that return scalar floats (e.g., `SDL_GetWindowDisplayScale`, `SDL_GetSurfaceHDRHeadroom`). Under the System V AMD64 ABI, float return values are passed in `%xmm0`.
- **Compiler Conflict**: GCC refuses to compile any function returning `float` when `-mno-sse` is specified (`error: SSE register return with SSE disabled`).
- **Kernel Restriction**: The ArenaOS kernel does not save or restore FPU/SSE state in `switch_context`, and does not enable `CR4.OSFXSR` (bit 9). Executing any SSE instruction in ring 3 generates an Invalid Opcode Exception (`#UD`), while unmanaged register use would corrupt inter-thread state.
- **Resolution Path**: Luna owns Phase 14 CPU architecture and must implement per-thread FXSAVE/FXRSTOR and `CR4.OSFXSR` enablement before floating-point code can execute in ring 3.

### 4.2 Blocker B2: Executable Image Registration Budget
- **Root Cause**: In `kernel/kernel/src/image_registry.rs`, dynamic executable registration is constrained to:
  $$\text{MAX\_BYTES} = 256\text{ KiB}\quad (262,144\text{ bytes})$$
  $$\text{MAX\_LOAD\_PAGES} = 128\text{ pages}\quad (524,288\text{ bytes span})$$
- **Upstream Footprint**: The genuine upstream SDL3 static archive (`libSDL3_upstream.a`) containing 53 modules is 729 KiB. A fully linked application without aggressive module pruning or dead-code elimination risks exceeding the 256 KiB file limit or 128 load-page budget.
- **Resolution Path**: Aggressive static library pruning with `-ffunction-sections -fdata-sections -Wl,--gc-sections` and freestanding libc stubbing are required to maintain binary size under 256 KiB.
